# Veda2：stage1（冻结 backbone、只训 adaptor）下的改法

## 目标

在**不改 kernel、不降速度**的前提下，把 stage1 的效果做到最好。stage1 的目标函数就是
ε，即稀疏输出相对稠密教师的误差（定义见 [sol_ablation](sol_ablation.md) §1），因为
backbone 冻结、模型不会自己适应稀疏。

结论先写：**Veda2 = 块质量目标 + 打分器补上「块行数」与「二阶矩」两个特征 + 静态的每头
预算**。三项都是零推理成本、零 kernel 改动。实测在 16:9@37 上每头 ε 中位数降 8~12%，
加上每头预算再降约 6%。**零阶补偿不进 Veda2**，理由见 §5。

## 1. 诊断：瓶颈是打分器，而且是结构性的

[sol_ablation](sol_ablation.md) 已经量出：打分器不准要吃掉 18~43% 的误差，是换蒸馏目标
（7~10%）的 2.4~4.3 倍。本文档回答「那打分器该怎么改」。

关键观察是**打分器的初始化本身就是在估计块的对数质量**。`predictor.py` 把 P 初始化成
N(0, 1e-4)，于是未训练的打分器精确等于均值池化的 QK，而那正是块对数质量的零阶项：

```
log E_ij = log B_j + Qbar_i . Kbar_j / sqrt(D) + Qbar2_i^T Cov_j Qbar2_i / (2D) + ...
            ^^^^^^^   ^^^^^^^^^^^^^^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
            缺失      现有打分器只有这一项          缺失
```

两个缺失项都**不是容量问题，是特征问题**：

- `log B_j` 是块里真实行数的对数。打分器看不到行数，所以它把一个只有 32 行真实 key 的
  补齐块和一个 128 行的满块排在同等位置。但块的注意力**质量**与行数成正比。
  16:9@37 的 (37,24,42) 网格用 4x4x8 排列要补到 (40,24,48)，最后一个 t 块只有 1/4 真实
  帧、最后一个 w 块只有 2/8 真实列，所以补齐块占比不小，这个偏差是系统性的。
- 二阶项需要 query 侧的 `E[q^2]` 和 key 侧的 `Var(k)`。双线性形式作用在
  `[mean|max|min]` 上，而方差是均值的二次函数，线性投影**构造不出来**，无论怎么训。

一个自洽的细节：现在的蒸馏目标是块内**最大**概率 `Mx`，而 max 几乎不随块行数变化，所以
「看不到行数」在 max 目标下是**正确的**。也就是说目标和特征是配套的——要改一个就得改另一个。

## 2. 实测：两个缺失项各值多少

16:9@37（38010 token、366 tile）、8 步 Turbo 教师 + step600 LoRA、`moviegen_holdout20`
2 条 prompt × 步 {0,2,5,7} × 50 层 × 56 头 × 6 个密度 = 134400 行，每头抽 6 个 query tile。

「补回的差距比例」= `(ε_proxy − ε_变体) / (ε_proxy − ε_oracle)`，0 表示和未训练的池化分数
一样，1 表示和知道答案一样好：

| ρ | proxy（现状） | +log B | +对角二阶 | +完整二阶 | A（质量 oracle） | Mx（最大 oracle） |
|---|---|---|---|---|---|---|
| 5% | 0.0% | **36.3%** | **46.0%** | 38.8% | 92.9% | 63.6% |
| 10% | 0.0% | 27.2% | **32.9%** | 33.6% | 92.1% | 82.2% |
| 20% | 0.0% | 21.9% | **26.9%** | 33.6% | 94.1% | 85.3% |

三件事：

1. **光加 `log B` 就补回 22~36%**，而它是每块一个常数，从 layout 直接读，成本为零。
2. **对角二阶项再加到 27~46%**，而且**稀疏度越高收益越大**，正好是稀疏加速关心的区间。
3. **完整二阶项并不更好**：ρ=5% 时对角（46.0%）反而**超过**完整（38.8%）。截断的累积量
   展开本来就不保证加更多项更准，而完整项需要 rank D² 的双线性，推理期根本付不起。
   **便宜的那个版本已经够了**，这是 Veda2 能零成本的关键。

逐头配对看（不是中位数之比，而是每个头自己比自己）：

| ρ | 对角特征的 ε 收益中位数 | p10 | p90 | 变差的头 |
|---|---|---|---|---|
| 5% | +8.1% | −0.2% | +20.9% | 10.4% |
| 10% | +9.8% | +0.6% | +23.0% | 9.0% |
| 20% | +12.1% | +1.0% | +25.6% | 8.8% |

约 9% 的头会变差，这是因为上表用的是**写死的精确系数**。换成可学习的低秩头之后，每个头
可以把系数学到 0，这个下行基本应该消失——这也是选「可学习低秩头」而不是「硬编码公式」
的理由。

### 2.1 训练循环自己的指标：和发布的训练过的打分器三方对比

上面的 ε 是本文档自己的度量。再用 stage1 训练循环**已经在看**的指标验一遍
（`heatmap.mask_diagnostics` 的 `recall` / `heat_kept`），把**发布的 8NFE step600
打分器**也拉进来做第三方：16:9@37、ρ=0.1（与 bundle 自己的 keep_ratio 一致）、
**用 bundle 自带的方案表**（4 种 tile 形状，不是均匀的 4x4x8）、一条 clip ×
步 {0,2,5,7} × 50 层 = 2400 行。

`veda1` 是今天的打分器初始化（`second_order_rank=0`），`veda2` 是全秩低秩头加
`init_exact_second_order_()`，两者**共享同一套基础投影**（单测用 `torch.equal` 钉死），
唯一区别就是二阶头。`veda1_trained` 是发布的权重。

**目标 = `max`（Veda 现在真正蒸馏的东西）**：

| 打分器 | recall | heat_kept | kept/天花板 |
|---|---|---|---|
| veda1（未训练） | 0.5308 | 0.4929 | 0.7679 |
| **veda1_trained（600 步）** | **0.5620** | **0.5212** | **0.8119** |
| veda2（未训练） | 0.5465 | 0.5040 | 0.7852 |

**目标 = `sum`（块质量，也就是真正决定 ε 的量）**：

| 打分器 | recall | heat_kept | kept/天花板 |
|---|---|---|---|
| veda1（未训练） | 0.6935 | 0.6378 | 0.9023 |
| veda1_trained（600 步） | 0.6756 | 0.6425 | 0.9091 |
| **veda2（未训练）** | **0.7189** | **0.6468** | **0.9151** |

三件事，按重要性排：

1. **在决定 ε 的那个度量下，未训练的 veda2 已经追平甚至超过训练过的 veda1。**
   recall 0.7189 vs 0.6756（+4.3 个点），`kept/天花板` 0.9151 vs 0.9091。
   `heat_kept` 只多 0.0043（+0.7% 相对），这是加权后的量、也是更该信的那个，所以
   **别把它读成"白送 600 步训练"**；诚实的说法是：**不训练就已经不落后。**
2. **用 max 做目标把打分器往离质量更远的地方推了。** 训练过的打分器对**质量** oracle 的
   recall 比未训练的**更低**（0.6756 vs 0.6935）。`heat_kept` 还是略涨（0.6378 →
   0.6425），所以不是纯倒退，但按质量这个标准排序确实变差了。这正好印证 §1 的结构论证：
   打分器的初始化本来就在估计质量，拿块内最大值去蒸馏是在和它的自然位置对抗。
3. **在 max 目标下，二阶头白送的量约等于 600 步训练的一半。** 训练把 recall 从 0.5308
   抬到 0.5620（+3.12 点），二阶头的初始化抬到 0.5465（+1.57 点）。

要说清楚的边界：这一轮**没有训练 veda2**。它证明的是起点更好，不是训练后更好；一个训练过
的 veda2 可能更好，也可能把二阶系数学歪，没测。而且只有一条 clip、一种几何。真正的训练
对比是 §7 的待办 1 和 2。

## 2.2 端到端：真实生成、真实测速、真实视频

`recall` / `heat_kept` 只是掩码和 oracle 的重合度，不是输出质量。所以跑了完整的
8 步去噪，三路同 seed、同 prompt、同几何，并实测每步时间。

设置：1:1@37（**768×768、124 帧、21312 video token**，最小的几何）、**ρ=0.05**、
`moviegen_holdout20` 里**全部 5 条**该长度的 clip、1×RTX PRO 6000 Blackwell、
FA4 块稀疏（sm_120，vendored 补丁）。ρ=0.05 下即使 oracle 也只保住 **50~56%** 的块
质量（实测，`runs/sol_initprobe_1x1_t37`），所以这是稀疏最吃力的区间。

### 速度（5 条 clip 的均值，排除 step 0 的 kernel 编译）

| 路线 | 每步 | 注意力 | 每步加速 | 注意力加速 |
|---|---|---|---|---|
| Dense | 5.450 s | 1.920 s | 1.00× | 1.00× |
| Veda1（发布的 step600） | 3.944 s | 0.468 s | 1.38× | 4.10× |
| Veda2 rank 128，池化未融合 | 4.209 s | 0.746 s | 1.29× | 2.58× |
| **Veda2 rank 16，池化已融合** | **3.938 s** | **0.475 s** | **1.38×** | **4.04×** |

**最后一行和 Veda1 在噪声以内**（每步 3.938 对 3.944 s，注意力 0.475 对 0.468 s）。

拿到这一行需要两步，而且**顺序和直觉相反**：

1. **只降 rank 完全没有用。** rank 16 在池化还没融合时实测仍然是 4.2 s/step、注意力
   0.7 s，和 rank 128 一模一样。也就是说 +0.278 s 的开销**根本不在 n² 项上**，
   §3.1 那套「二阶项是又一个 rank-D 双线性所以要给它低秩」的成本分析，方向对但量级错了。
2. **开销全在池化。** `_gather_and_pool` 用的融合 gather kernel 只写
   `[mean|max|min]`，所以两个二阶矩原来是事后再调两次 `pool_tiles`，把 tile 序的 q/k
   又读了几遍（中心化方差还要读两遍）。把它们塞进那个 kernel 之后开销就没了：
   **tile 本来就已经在寄存器里**，连中心化方差都不要额外的内存流量，因为均值在同一个
   kernel 里刚算完。

低秩头仍然要留着，但理由变了：它省的是**参数和显存**（bundle 从 734 MB 降到 547 MB），
不是时间。

### 闪烁：为什么这条观察比 ε 更重要

人工确认给出的不是「稍好」而是一个**定性的失效消失了**，而 ε 看不到它。ε 是逐层标量，
对时间维取了平均；闪烁是**时间一致性**的失效，平均之后正好被抹掉。

机制上这和「块内最大值 vs 块质量」直接对应：

- 块内最大值是**极值统计量**，由单个 token 对决定，方差大。相邻帧的同一个 query tile
  很容易因为一个 token 的抖动就换掉所选的 key 块。
- 块质量是 128×128 项的**和**，是平均统计量，方差小得多。

tile 形状是三维的（如 4x4x8 跨 4 帧），所以**选块的不稳定直接表现为跨帧上下文不一致，
也就是闪烁**。Veda1 对着极值统计量蒸馏，Veda2 对着和统计量，这是闪烁差异最自然的解释。

这给出一个可量化的代理指标：**掩码抖动**（同一 query tile 在相邻去噪步之间、以及时间上
相邻的 query tile 之间，所选块集合的重合度）。见 §7 待办。

Sol 没有进这一轮对比（用户标为可选）：它的两个机制都已被实测否掉（§5 与
[sol_ablation](sol_ablation.md) §3），而把它的 `μ+βσ` 阈值接进推理路径要改
`miowtion/veda/mask.py`，那个文件被别的 agent 占用。

复现：

```bash
python scripts/bolt_veda2.py --in <released bundle> --base reset \
    --out weights/veda/veda2_untrained.safetensors
python scripts/generate.py --config configs/infer_veda2_1x1_t37_sparse05.yaml
python scripts/generate.py \
    --config configs/infer_veda2_1x1_t37_sparse05_veda2.yaml
# then one scripts/visual_check.py per clip, three --video panes
```


## 2.3 训练：六次失败，而根因只有一个（见 §2.6）

§2.1 和 §2.2 的所有 Veda2 数字都是**完全 training-free** 的：投影是全新的 N(0,1e-4)，
二阶头和 count gain 在闭式系数上。那自然引出一个问题——训练能不能在这之上再加分。
目前的答案是「还不知道」，但五次尝试把**不是**原因的东西排除掉了，这些排除本身就是结果，
而且第五次之后它们有了**一个共同的解释**（§2.4）：损失必须对 top-k 读出看不见的那两个
规范方向（逐行偏移、逐行尺度）不变，否则梯度会去调规范而不去调排序。

接线在 `TrainConfig` 上：`second_order_rank` / `count_term` 直通打分器，
`heat_reduce` 选蒸馏目标，`kl_direction` 选 KL 方向，`kl_weight` / `topk_weight` 配比，
`freeze_second_order` 冻住二阶头。默认全是 Veda1。

### ① forward KL 和它要优化的东西反向

`seer_kl` 原本算的是 KL(teacher ‖ student)，即 **forward** 方向。Forward KL 是
**覆盖型**的：教师哪里有质量、学生在那里概率低就被重罚，所以**摊平是最便宜的降损方式**。

实测，25 步：**KL 从 134 降到 48（−65%），同期 recall 从 0.714 掉到 0.654。**
损失被最小化了，而要的东西变差了。这不是权衡，是目标选错。

它也解释了那个荒谬的量级。logit spread 为 $\sigma$ 时 $\log p_j\approx-(S_{\max}-S_j)=O(\sigma)$，
所以 forward KL $\approx\sigma(1-t_{\max})$——**最小化它等于压缩 logit 幅度**，不是学排序。

`seer_kl` 现在有 `direction`。**reverse** 是 KL(student ‖ teacher)，**寻峰型**：学生只因为
在教师没质量的地方放质量而被罚。教师的零 floor 在 1e-6，所以损失有界（约 14）而不是跑到 300。
单测钉的是两者的定义性差别：尖锐的学生在 reverse 下赢、在 forward 下输。

### ② 从 Veda1 warm start 更差，而且是 init 时就更差

直觉上该复用那 600 步学到的特征提取。实测相反，同 keep_ratio、同几何轮转、step 1：

| 初始化 | recall | logit_std | grad_norm |
|---|---|---|---|
| warm start（Veda1 训练过的基础） | 0.6310 | 192~275 | 7522 |
| from scratch（重置的基础） | **0.7557** | 192~277 | 2037 |

**重置的基础领先 12.5 个点。** 闭式项和**未训练**的基础组合得上，和**对着块内最大值训过**的
基础组合不上——和 §7 里 bolt 失败是同一个失配。600 步特征学习不值得落后 12 点开场。

### ③ reverse KL 把 logits 跑飞了

换成 reverse 之后损失量级正常了（0.275 对 209），但 48 步之内：

| 步 | recall | kept/ceiling | reverse KL | logit_std |
|---|---|---|---|---|
| 1–12 | 0.7308 | 0.9185 | 0.2872 | 111 |
| 13–24 | 0.6905 | 0.9064 | 0.3390 | 171 |
| 25–36 | 0.6573 | 0.8895 | 0.4060 | 365 |
| 37–48 | 0.6401 | 0.8821 | 0.4430 | 664 |

**损失自己在上升**，所以这不是权衡而是发散。机制是二阶头的**二次耦合**：
项是 $AB^\top$ 的双线性，$\partial S/\partial A\propto A$，而 Adam 步长与梯度大小无关，
所以 $A$（初值 0.0625）每步漂 1.6%、48 步漂 77%，乘积动 3 倍。
`freeze_second_order` 就是为这个加的；冻住之后发散消失。

### ④ 我用 12~59 步评判了一件需要几百步的事

这一条不是运行失败，是**我的判断错**，记下来因为它比前三条更容易再犯。

Adam 的步长 ≈ lr，**与参数自身尺度无关**。`proj` 初值 **1e-4**，而发布版训练之后是
**1.15e-2**。所以 lr 1e-3 是**每步 10 倍相对变化**，12 步就走完了到有用尺度的全程，
把那个物理上正确的零阶估计量覆盖成了 12 步噪声。而 Veda1 是 **600 步 + step 170 的
warm start** 才收敛的。早期回落是旅程的一部分。

于是试了 lr 1e-4（慢 10 倍），50 步**什么都没动**：逐几何都在起点 0.01 以内。
所以问题不是「精炼还是覆盖」，而是「**学一个投影**」对「**保留闭式**」，只有跑完全程能答。

### 两个 guard，各管一件事

一次下降跑了 59 步才被看到，等于一小时 GPU 花在 20 步就能看出的结论上。所以：

| | 判据 | 适用 |
|---|---|---|
| `train.monitor.EarlyAbort`（**默认开**） | `max_drop`：跌破起点超阈值 | **长跑**。两次真失败都是这个形状，且不在乎跑了多久 |
| 同上 | `patience`：trailing mean 不创新高 | 只适合短诊断跑。它曾把一次「只是平的」运行砍在第 50 步 |
| `scripts/watch_training.py` | 以上两条 + `stall` | 外部，额外抓**停止写日志**：挂在 kernel、卡在 NFS、被杀没 traceback，三种今天都发生过 |

两个判据都不给会直接报错，而不是悄悄永不开火。比较一律用 **trailing mean**，因为四个几何
轮转造成的波动比进展本身大——单步根本不可比。


### 更正：`log B` 的收益取决于块行数的**离散程度**，不是补齐比例

我原先写的是「`log B` 的收益直接取决于补齐块的比例」。**那是错的**，另一个 agent 在双采
几何上的复测（中位比 ≈1.00，平均误差略差）把它推翻了，而两边的测量都是对的。

机制：`log B_j` 是**每列一个常数**，所以给第 $j$ 列加常数只在这些常数**彼此有差别**的
程度上改变 top-k。预测量是 $\mathrm{std}_j(\log B_j)$ 相对于基础分数的 spread，
而补齐**比例**根本不是预测量——这个例子里它甚至指向相反方向：

| 几何（4x4x8） | tile 数 | 补齐比例 | **std(log B)** | 行数范围 | 相对 base spread 3.9 |
|---|---|---|---|---|---|
| 16:9@37 | 360 | **19.1%** | **0.664** | 8 ~ 128 | 17% |
| 双采第一段 8x14x72 | 72 | 12.5% | 0.302 | 64 ~ 128 | 8% |
| 双采第二段 15x27x72 | 252 | **9.6%** | **0.160** | 72 ~ 128 | **4%** |

原因是**补齐在各轴上是乘性的**。16:9@37 在 t（37/40）和 w（42/48）两个轴上同时短，
所以角落的 tile 只有 **8** 行真实 key，`log B` 跨列差到 $\log(128/8)=2.77$。双采那两个
几何只有一个轴短，没有任何 tile 低于半满，于是同样的 base spread 下杠杆小 4 倍——
**那是 null 而不是矛盾**。

`solattn.count_term_leverage(grid, shape)` 把这件事做成了**纯静态**的计算：只看
layout，不需要 GPU，所以上任何几何之前都能先查一眼这一项值不值得开。

实践上的结论：`count_gain` 本来就是**每头一个可学习标量、初值 1**，所以在没有杠杆的几何上
训练可以把它压到 0。但我不能再声称那 22~36% 是普适的——**它是 16:9@37 这个 layout 的
性质**。

### ⑤ 居中的 BCE：loss 在 3 个几何上**涨**

把 oracle top-k BCE 逐行居中（减掉该行均值）解决了「loss = 偏置」那个病：二阶项是
非负乘积之和，也就是一个很大的正偏移，居中之前那个偏移**就是** loss 本身（537，
grad_norm 7522 对着 clip 1.0）。居中之后 loss 回到 O(10)，梯度范数 0.5~0.79，
远在 clip 以下——优化器确实在做有效更新。然后：

| 几何 | n | BCE | | `kept/ceiling` | |
|---|---|---|---|---|---|
| 16:9@37 | 3 | 49.15 → 64.21 | **涨** | 0.9037 → 0.8831 | 跌 |
| 1:1@37 | 2 | 22.97 → 31.62 | **涨** | 0.9343 → 0.9346 | 平 |
| 4:3@37 | 4 | 8.86 → 13.73 | **涨** | 0.9239 → 0.9019 | 跌 |
| 9:16@37 | 4 | 26.72 → 24.29 | 跌 | 0.9091 → 0.8934 | 跌 |

（必须**逐几何**看：四个几何轮转，混在一起的曲线不可比。）

四个几何里有三个**损失和指标同时变坏**，这不是「优化目标和指标不一致」那种常见病，
而是更难看的一种：在做有效更新的前提下，被优化的那个量自己在涨。到这一步为止的五次
尝试各自都有解释，但没有**一个**解释。下一节是那个解释。

## 2.4 统一的诊断：目标必须对决策的规范不变

五次尝试是**同一个病**。top-k 读出对分数的**逐行正仿射变换完全不变**：给某一行所有
分数加一个常数，或者把整行乘 3，选出的块**一个都不变**。所以分数里有两个方向是
kernel 结构上看不见的——逐行偏移和逐行尺度。如果损失对这两个方向敏感，梯度就可以
在**不改变任何一个选择**的前提下把损失降下去，于是它就会去那里：那是最便宜的下降
方向。

| 目标 | 逐行偏移不变 | 逐行尺度不变 | 实测症状 |
|---|---|---|---|
| forward KL | ✓ | ✗ | 把 spread 压平：KL 134→48 而 recall 0.714→0.654 |
| reverse KL | ✓ | ✗ | 无限制锐化：48 步内 `logit_std` 涨 6 倍 |
| 原始 BCE | ✗ | ✗ | 饱和：loss = 偏移 = 537，grad_norm 7522 |
| 居中 BCE | ✓ | ✗ | 3/4 几何上 loss 涨（上一节） |
| **`transport_loss`** | **✓** | **✓** | 本节 |

forward / reverse KL 对尺度敏感的方式正好相反（一个 mass-covering 所以压平，一个
mode-seeking 所以锐化），这解释了为什么它们失败的形状互为镜像——也说明「换个方向」
这条路上没有答案，**两个方向都不满足判据**。

### 把 attention 读成一侧的熵正则最优传输

[arXiv 2508.08369](https://arxiv.org/abs/2508.08369) 指出 softmax attention 的一行
就是一个**一侧归一化的熵正则 OT** 问题的解：

$$p_u = \arg\max_{p \ge 0,\ \mathbf{1}^\top p = 1} \langle p, s_u \rangle + H(p),
\qquad p_{uv} = \frac{e^{s_{uv}}}{\sum_{v'} e^{s_{uv'}}}$$

块稀疏在这个框架里**不是近似，是支撑集约束**：只允许往块集合 $S$ 里的列运输。把
约束代进去，可达的最优值有闭式

$$F(S) \;=\; \max_{\substack{p \ge 0,\ \mathbf{1}^\top p = 1 \\ \mathrm{supp}(p) \subseteq S}}
\langle p, s_u \rangle + H(p) \;=\; \log \sum_{v \in S} e^{s_{uv}} \;=\; \log E_u(S)$$

于是**三件事同时掉出来**，都不需要任何近似：

1. **目标是质量，不是峰值。** $\arg\max_{|S| = k} F(S)$ 就是**按块注意力质量取
   top-k**，逐位精确。§2 里测到「块质量 ≈ 理想重要度（差 1.6%），块最大值差 7~10%」
   是经验结果；这里它是**推出来的**：$F$ 是 $\log$-sum-exp，块最大值不是任何
   OT 问题的值。这也是 `transport_weight` 要求 `heat_reduce: sum` 的原因，配置里
   直接报错而不是悄悄用错的目标。
2. **选择丢掉的价值有闭式。** 丢掉的质量占比记为 $r_u = 1 - E_u(S)/E_u(\text{all})$，
   则 $F(\text{all}) - F(S) = -\log(1 - r_u)$。这正好是 `heat_kept / heat_ceiling`
   这个指标在量的东西，也就是说**指标本身就是 OT 的次优间隙**，不是它的代理。
3. **Veda1 的未训练打分器就是零阶项。** 对 $F$ 做累积量展开，首项是
   $\log B_j + \bar Q \cdot \bar K / \sqrt{D}$——均值池化的 QK 加上块行数。这是
   §1 那个「结构性缺口」论证的 OT 版本，而且给出了缺的是**哪一项**（二阶累积量）。

### `transport_loss`：保留质量占可达质量的比例

学生不能直接输出一个集合（不可微），所以放松的**只有选择**这一步：把 k-hot 指示
函数换成关于该行自己第 k 大分数的 sigmoid——

$$z_u = \frac{s_u - \mathrm{mean}(s_u)}{\mathrm{std}(s_u)}, \qquad
\theta_u = \frac{z_{u,(k_u)} + z_{u,(k_u+1)}}{2}, \qquad
\pi_u = \sigma\!\left(\frac{z_u - \theta_u}{\tau}\right)$$

$$\mathcal{L}_u = -\frac{\langle \pi_u,\ a_u \rangle}
{\langle \mathrm{oracle}_u,\ a_u \rangle}$$

$a_u$ 是教师的块质量，$\mathrm{oracle}_u$ 是同一个预算下按 $a_u$ 取的硬 top-k，
$k_u$ 由 `select_video_blocks` 给出（**逐行**，因为 layout 规则让预算逐行不同）。
关键性质，五条都有单测：

- **$\tau \to 0$ 时它逐位等于 $-\,$`heat_kept/heat_ceiling`**，也就是判这次训练
  成败的那个指标本身。损失和指标是**同一个对象**，不可能反向移动——而 forward KL
  （KL 134→48 而 recall 0.714→0.654）和居中 BCE（3/4 几何 loss 涨）正是反向移动了。
  oracle 自己的选择给出恰好 $-1$。
- **逐行正仿射完全不变**：$z$ 把偏移和尺度都除掉，$\theta$ 又是 $z$ 的函数，所以
  $s_u + 7$、$3 s_u$、$0.01 s_u$、$5 s_u + 100$ 给出**逐位相同**的损失
  （`torch.equal` 级别，不是容差）。这是前四个目标缺的那条。
- **梯度在规范方向上恰好为零**，不是「小」：标准化的 backward 把常数方向和径向
  分量都投影掉了，所以**没有任何一次更新能花在规范上**。
- **梯度集中在 rank-k 边界**，因为 $\sigma'$ 在那里取峰值。实测 $n=360$、$k=36$、
  $\tau=0.15$：90% 的梯度权重由 **58** 个块承担，其中 76% 落在距切点 $\pm 2\tau$
  以内。
- **policy 恰好花掉预算**（$\pi$ 按 $k_u/\sum_j \pi_{uj}$ 重标定）。这条不是修饰：
  不加的话**平坦的预测器会赢**——$z \equiv 0$ 让每一列都拿 $\sigma(0)=0.5$，等于
  「每个块都留一半」，实测损失 $-1.33$，**比 oracle 还好**。那就是 forward KL 的病
  （可以靠摊平降损失）从放松里重新爬进来。$\tau \to 0$ 时 $\pi$ 已经精确是 k-hot，
  所以重标定在极限下是恒等变换，上面第一条仍然成立。

**第一版用的是整行 softmax 作为 policy，那是错的放松**，记下来因为它看起来完全合理：
在标准化分数上、$n=360$ 时，softmax 的有效支撑是 **220 个块**，只有 **39%** 的权重
落在预算之内，于是绝大部分梯度在问 kernel 永远不读的那些排名。它跑了 4 个 update
就被这个静态计算换掉了。

$\tau$ 的取法：$z$ 已标准化，所以 $\tau$ 跨头跨几何可比。标准正态在 10% 分位
（$z \approx 1.28$）的密度是 0.175，所以 $\tau = 0.15$ 的过渡带约覆盖
$0.035n$ 个块——$n=360$ 时约十来个，宽到有梯度，窄到那是**关于决策**的梯度。

实现 `veda/heatmap.py:transport_loss`，接线 `train/trainer.py:TrainConfig.transport_weight`
（与 `kl_weight` / `topk_weight` 并列，三者可加权共存；配置里
`transport_weight` 与 `heat_reduce: max` 同时出现会直接报错），配置
`configs/stage1_veda2_transport_t37.yaml`。启动一律走
`scripts/launch_training.sh <config> <tag>`，它把 trainer 和外部 watcher
作为一个整体起起来——分开起就会忘掉第二个。

### ⑥ 目标对了，优化器错了：AdamW 在 warmup 里就把每个几何都做坏了

`transport_loss` 的第一次运行用的是 AdamW lr 1e-3（沿用前几次的配置，**这是个错误**）。
14 个 update 之后，逐几何看：

| 几何 | transport | `kept/ceiling` | recall |
|---|---|---|---|
| 4:3@37 | -0.8333 → -0.7902 | 0.9300 → 0.9037 | 0.763 → 0.681 |
| 9:16@37 | -0.7948 → -0.7581 | 0.9106 → 0.8926 | 0.716 → 0.669 |
| 16:9@37 | -0.7904 → -0.7653 | 0.9109 → 0.8987 | 0.694 → 0.670 |

**四个几何全部变差，三个指标全部同向**——而且这还在 warmup 里，lr 只走到 7e-4。
注意这一次和前五次不同：损失和指标是同一个对象，所以「指标掉了」就等于「损失涨了」，
没有解释空间。

原因不是目标，是**步长语义**。这是个找尺度的问题：base projection 初值 **1e-4**，
有用尺度 **1.15e-2**（相差 115 倍），而 AdamW 的步长 ≈ lr，**与权重当前大小无关**。
lr 5e-4 打在 1e-4 的权重上就是**每步 5 倍的相对改变**，闭式初始化撑不过十几步。

Muon 在这里不是「更快的 AdamW」，而是**步长语义正确的那个**：正交化之后把更新的 RMS
显式标定到 `lr × muon_rms`，所以步长是配置的性质而不是梯度大小的函数，而且
`update_rms` / `update_align` 每步都是实测值进日志。打分器又恰好是 50 层 × 两个
每头独立矩阵、没有 embedding / bias / norm，是 Muon 唯一适用且不用拆优化器的形态
（`docs/features/training.md`：同 seed 从头训，第 20 步层 49 的 KL 只有 AdamW 的
1/2.7）。

配置 `configs/stage1_veda2_transport_muon_t37.yaml`，`abort_max_drop` 从 0.12 放到
**0.35**：这一臂的起点是**已经达标**的闭式初始化（`kept/ceiling` 0.934），所以前几百步
是**离开一个好分数的旅程**而不是退步，从头训会合理地经过 0.60~0.75。按 warm start 调的
guard 会正好砍掉这次运行要测的那段路（§2.3 ④ 就是这么砍的）。guard 要抓的仍然是跑飞，
而跑飞远不止 0.35。

## 2.5 两件必须量过而不是推过的事

### 训练目标和 `kept/ceiling` 确实是正关系，但它们不是同一个量

先说结论：**在一条 clip 内，`-transport` 和硬选择指标的 Spearman 是 0.9997**，
360 个 key tile、对数正态块质量、覆盖 1.00 到 0.50 的全质量区间，逐对比较只有
0.3% 反向。温度也不是问题：$\tau$ 从 0.5 扫到 0.03，soft 和 hard 的 Spearman 始终
在 0.9998 以上。所以**优化这个损失就是在优化那个指标**，这件事是量出来的。

但真实 run 的 37 个点上池化 Spearman 只有 **0.945**（逐几何 0.90 ~ 0.99）。差额来自
两个定义上的不一致，我原来以为它们可以忽略：

| 差别 | `transport_loss` | `heat_kept/heat_ceiling` |
|---|---|---|
| 强制对角 | **排除** | 计入 |
| 跨行归约 | 逐行比值再平均 | 行平均之后再相除 |

归约顺序几乎无害（单独隔离时 Spearman 0.9999）。**对角才是问题**，而且只在跨 clip 时
发作：对角块占多少质量是**片子的性质**，不是打分器的决定。构造实验——同一批打分器、
六条 clip、对角质量从 0 加到 100——池化 Spearman 从 **0.9997 掉到 0.9937**，逐对反向
从 0.3% 升到 **3.1%**。也就是说计入对角会让这个指标**比目标本身更不可跨 clip 比较**，
而四个几何轮转的训练正是在跨 clip 比较。

对策：`mask_diagnostics` 多报一个 `retained`，定义就是 $\tau \to 0$ 的
$-\mathcal{L}$（排除对角、逐行比值再平均），单测把它和 `transport_loss` 钉在
`abs=1e-4`。于是**日志里的指标和被优化的量是同一个对象**，watcher 也该跟它。
`heat_kept` / `heat_ceiling` 保留，因为 ceiling 本身仍然要看——它说的是教师够不够集中，
这件事训练改不了。

### forward / reverse KL 的失败，在 EOT 里是同一个参数的两个方向

两件可验证的事实。

**一、forward KL 就是 EOT 对偶势的 Bregman 散度。** 取 $F(s) = \log\sum_v e^{s_v}$
（约束下的 EOT 最优值），则

$$D_F(s_S, s_T) = F(s_S) - F(s_T) - \langle \nabla F(s_T),\, s_S - s_T \rangle
= \mathrm{KL}(p_T \,\|\, p_S)$$

因为 $\nabla F = \mathrm{softmax}$。实测两边差 1e-6（fp32 噪声）。所以 forward KL
**不是一个任意选择**，它是这个 EOT 问题自带的那个散度，住在**对偶（分数）空间**；
reverse KL 把两个参数交换，住在**原始（plan）空间**。

**二、逐行尺度就是 EOT 的温度 $\varepsilon$。** EOT 在正则强度 $\varepsilon$ 下的解是
$\mathrm{softmax}(s/\varepsilon)$，所以把分数乘 $\alpha$ 等价于取
$\varepsilon = 1/\alpha$。而固定 $k$ 的 top-k 对 $\alpha$ **完全不变**。实测：学生
排序固定、只扫 $\alpha$——

| $\alpha$ | $\varepsilon$ | forward KL | reverse KL | logit std | **保留质量** |
|---|---|---|---|---|---|
| 0.35 | 2.86 | 0.7641 | 0.8060 | 0.63 | **0.8713** |
| 0.75 | 1.33 | **0.3785** | 0.3914 | 1.35 | **0.8713** |
| 1.00 | 1.00 | 0.3869 | **0.3874** | 1.80 | **0.8713** |
| 2.50 | 0.40 | 2.7699 | 1.5189 | 4.50 | **0.8713** |
| 4.00 | 0.25 | 6.3081 | 2.0573 | 7.20 | **0.8713** |

保留质量在每一行都**恰好不变**，而两个 KL 各自有不同的最小点：forward 在
$\alpha = 0.75$（要更平的 plan），reverse 更靠右，而且对过度锐化的惩罚只有 forward
的 1/3（$\alpha=4$ 时 2.06 对 6.31）。

于是 §2.3 ① 和 ③ 不再是两个经验观察，而是**同一个量的两个符号**：

- forward KL 是覆盖型，$p_S \approx 0$ 而 $p_T > 0$ 的地方罚得无穷大 → 推高
  $\varepsilon$ → 摊平。实测 spread 3.78 → 2.65。
- reverse KL 是寻峰型，$p_S > 0$ 而 $p_T \approx 0$ 的地方罚 → 压低 $\varepsilon$ →
  无限锐化。实测 `logit_std` 48 步涨 6 倍。

**换方向这条路上没有答案，因为两个方向都在调同一个 kernel 看不见的参数。** 正确的做法
是先把 $\varepsilon$ 规范固定（逐行标准化），这正是 `transport_loss` 做的事。

一个由此而来的、尚未试的候选：**规范固定之后的 forward KL**。它是这个几何自带的那个
散度（上面第一条），强凸，而且**在所有列上都有梯度**；而 `transport_loss` 的梯度集中在
rank-$k$ 切点附近（实测 90% 落在 58 个块上），这对聚焦是优点，对**冷启动是缺点**——
排序整体错的时候，远离切点的块拿不到信号。所以合理的配方可能是
「早期规范固定 forward KL + 后期 transport」，或者两者加权。这条还没有实测，不要当结论。

实现 `veda/heatmap.py:gauge_fixed_kl`，开关 `TrainConfig.gauge_kl_weight`。两个构造细节
都是必要的，不是修饰：

- **先逐行标准化**，去掉 $\varepsilon$ 这个规范；
- **再搬到教师自己的尺度上**（乘 $\mathrm{std}(\log a)$、加 $\mathrm{mean}(\log a)$）。
  如果只标准化到单位方差，教师一般**不在** $\{\mathrm{softmax}(z): \mathrm{std}(z)=1\}$
  这个族里，损失会留下一个**不可约的偏置**（实测 0.291）——而不可约偏置正是原始 BCE
  不可用的那个病。搬到教师尺度之后，真值处的损失是 0（实测 1e-8），且对逐行正仿射不变
  到同样精度。

实测的那条区别也钉进了单测：六个 tile 的 fixture 上，`transport_loss` 把 85% 的
$|\nabla|$ 压在前两列，`gauge_fixed_kl` 只有 65%；两者的逐列梯度和都为零，所以**都**
不能靠平移或缩放来降。

## 2.6 根因：`proj = 0` 已经是闭式，根本没有「找尺度」这段路

前六次运行我都在同一个错误的前提上。

`LayerPredictor.embed` 是**残差**的：

```python
mean = feats[..., :self.head_dim]
return torch.bmm(feats, proj) + mean          # <- 残差
```

所以 **`proj = 0` 时 tile 嵌入就是均值池化特征，logit 恰好是闭式的零阶项**。
`proj` 是**在一个已经正确的答案之上的修正量**，不是一条必须跑完的路。发布权重的
`proj` RMS 是 1.15e-2，那是 Veda1 在**另一个目标**下跑 600 步学到的修正量的大小，
**不是一个必须冲过去的目的地**。我却按「从 1e-4 走到 1.15e-2 是 115 倍旅程」来定步长，
于是把 `abort_max_drop` 放到 0.35、把 lr 放到 1e-2，正好把那个精确项用噪声覆盖掉。

证据来自那一臂自己的 checkpoint，第 25 个 update：

| 量 | 值 |
|---|---|
| 初始化 `proj_q` RMS | 1e-4 |
| Veda1 训练后的修正量 RMS | 1.15e-2 |
| **第 25 步实测 `proj_q` RMS** | **1.65e-2**（已经越过训练后的尺度） |
| Muon 每步 RMS（`lr × muon_rms`） | 2e-3 |
| 25 步随机游走 $2\times10^{-3}\sqrt{25}$ | 1e-2（与实测同阶） |
| `update_align` 第 1 → 30 步 | 0.162 → **0.087** |

25 步长了 **165 倍**，而 align 0.087 说明其中绝大部分在**不服务于任何一批**的方向上。
所以那不是旅程，是**覆盖**：30 个 update 里四个几何逐几何单调下降（4:3 的
`kept/ceiling` 0.924 → 0.837，9:16 0.913 → 0.809），**而且被优化的损失自己也在单调上升**。

损失和梯度是对的，这点单独验过：在固定的一批上沿 $-\nabla$ 走，步长从 1e-3 到 10
每一个都让损失下降（$-0.6852 \to -0.8044$）。所以问题只在步长和方向。

### 步长模型被实测验证了

两臂在**同一个 update 25** 的 `proj_q` RMS：

| 臂 | lr | 每步 RMS | 预测的 25 步游走 | **实测 RMS** | 相对初始化 |
|---|---|---|---|---|---|
| journey | 1e-2 | 2e-3 | 1e-2 | **1.65e-2** | 165 倍 |
| refine | 5e-4 | 1e-4 | $10^{-4}\sqrt{25} = 5\times10^{-4}$ | **5.81e-4** | 5.8 倍 |

refine 臂的实测值和「随机游走」预测差 16%，也就是说**这个步长模型是对的**，可以用来定 lr
而不必试。`count_gain` 走 AdamW、lr 是基础的 0.1 倍，从 1.0 动到 1.00051，量级同样对得上
（25 步 × 5e-5）。

前 32 个 update 的结果：**崩塌消失了**。逐几何（每个 8 个点）：

| 几何 | `retained` 起点 | 第 25~32 步 |
|---|---|---|
| 16:9 | 0.8974 / 0.8947 | 0.9044 / 0.8979 |
| 4:3 | 0.9028 / 0.9074 | 0.9088 / 0.9085 |
| 9:16 | 0.8902 / 0.8859 | 0.8977 / 0.8877 |
| 1:1 | 0.9119 / 0.9087 | 0.9080 / 0.9081 |

三个几何略高于起点、1:1 基本持平，**没有任何一个在单调下降**。但增幅只有 0.003~0.005，
仍在 clip 间噪声范围内，所以**这还不是结论**，只是「问题现在可问」。

于是 `configs/stage1_veda2_transport_refine_t37.yaml`：

- **lr 5e-4**，步长 RMS = $5\times10^{-4}\times0.2 = 10^{-4}$，**正好是初始化的尺度、
  训练后修正量的 1%**。400 步的非相干累积是 $10^{-4}\sqrt{400} = 2\times10^{-3}$，
  只有有用尺度的五分之一，而相干部分还能到它的几倍。
- **momentum 0.5**，不是 0.95。缓冲平均 $1/(1-m)$ 个 update：0.95 跨 20 个，而每个
  update 只用一个几何、四个轮转，实测同几何梯度余弦 0.92、跨几何只有 0.05~0.57。
  0.95 让每一步都是四个互相冲突方向的混合。
- **`abort_max_drop` 0.06**，不是 0.35。既然 `proj = 0` 已经是闭式，就**没有谷底要穿**，
  持续下跌只能说明在覆盖正确项。
- watcher 跟 **`retained`**（§2.5），也就是和损失同一个量。

## 2.7 结论：训练有真实但有界的增益（+0.009），上限是结构不是优化

`configs/stage1_veda2_transport_refine_t37.yaml` 跑到第 104 个 update，逐几何各 26 个点，
对 step 做 OLS：

| 几何 | n | `retained` 斜率 / 100 步 | t | 残差 sd | `kept/ceiling` 斜率 (t) |
|---|---|---|---|---|---|
| 16:9@37 | 26 | **+0.01235** | 6.44 | 0.00287 | +0.01044 (5.3) |
| 4:3@37 | 26 | **+0.01465** | 4.23 | 0.00536 | +0.01282 (4.1) |
| 9:16@37 | 26 | **+0.01807** | 6.98 | 0.00399 | +0.01475 (5.9) |
| 1:1@37 | 26 | **+0.00698** | 2.51 | 0.00428 | +0.00579 (2.5) |

**四个几何全部上升、全部显著**，而且 `kept/ceiling` 独立同向（§2.5 说过这两个该一致）。
1:1 最小是合理的：它 tile 最少，预算覆盖的比例最大，可改进的空间本来就小。

`recall` **没有**趋势（t 从 −1.6 到 +1.6，两个为负）。这不是矛盾，正是 §2.5 量过的那件事：
质量在块集合对齐之前就饱和了，打分器把高质量块挑对了，换掉的是近乎零质量的块，而
`recall` 按块计数、不按质量加权，所以它看不见。**不要用 recall 判这件事。**

### 最终结果（第 163 个 update 停机，逐几何 40~42 点）

| 几何 | 起点 `retained` | 终点 | 净增益 | 全程斜率 / 100 | t |
|---|---|---|---|---|---|
| 4:3@37 | 0.89806 | 0.91237 | **+0.0143** | +0.00596 | 2.90 |
| 9:16@37 | 0.88787 | 0.90282 | **+0.0150** | +0.00901 | 6.42 |
| 16:9@37 | 0.89837 | 0.90264 | +0.0043 | +0.00241 | 1.84 |
| 1:1@37 | 0.90832 | 0.91100 | +0.0027 | +0.00310 | 2.25 |

**净增益平均 +0.009**，也就是可达质量的约 0.9 个百分点，在 100 个 update 内到手，之后平。
注意全程斜率比第 104 步时读到的（+0.007~+0.018）**小了一半**——那正是平台的签名：
后半段的平把全程斜率稀释了。半程分割证实了这点：前半四个几何全部显著（t 2.3~4.7），
后半四个全部不显著（t −1.8~+0.6）。

于是在 163 步停机：剩下的 237 步按证据不会再加东西。

### 为什么只有 +0.009：优化已经不是瓶颈，结构才是

**优化侧已经排除了**，三条证据：

- 步长模型实测验证到 16%（预测 5.0e-4、实测 5.81e-4）；
- 权重**相干**移动（见下表，线性于 $t$ 而非 $\sqrt{t}$，相干比例约 20%）；
- 没有发散（`logit_std` 全程无趋势）。

**真正的上限是三件结构性的事**：

1. **起点已经是闭式精确解，不是随机初始化。** `embed` 是残差的，`proj = 0` 就是精确的
   零阶项；二阶头冻结在精确对角系数上；`count_gain` 起于精确的 1.0（整程只动到 1.0027）。
   所以训练学的是**对一个解析正确答案的修正**，可改进的空间只有闭式弄错的那部分。
2. **闭式弄错的那部分，大半不在双线性能表达的范围内。** 目标是块质量的对数，即
   $128\times128$ 个分数的 log-sum-exp。累积量展开里零阶（$\log B_j$ + 均值池化 QK）和
   二阶（$\mathrm{tr}(C_q C_k)$）都已经在模型里，而二阶那项**低秩头的 rank 就是绑定约束**
   （实测对角特征补回 oracle 差距的 27~46%）。三阶及以上、以及尖峰区间里展开根本不收敛的
   部分，`[mean|max|min]` 池化上的双线性形式表达不了。
3. **每一步都有一部分梯度必然花在 kernel 看不见的方向上**（§2.7 的单调规范），而且这不是
   调参能解决的。

**几何差异支持结构解释而不是优化解释**：增益最小的是 1:1@37（+0.003），它 tile 最少、
预算覆盖每行的比例最大，闭式本来就最不容易弄错；增益最大的是 9:16 和 4:3（+0.015）。
**增益跟着 headroom 走，不跟着优化难度走。**

### 还没做的那一步：固定 holdout

以上全部测在**训练流**上，每个 update 换一条片子。`retained` 除掉了逐行 ceiling，已经把
大部分片子难度除掉了，而且每几何 40 个点的回归是正确的防御——但
`docs/features/evaluation.md` 说得很明确：同几何换片子 `heat_ceiling` 能差 4%，和要测的
效果同量级。所以 **+0.009 还没有在固定 holdout 上确认，也还没有当成视频看过**。

量级参照：training-free Veda2 超过训练过的 Veda1 是 recall 0.7159 对 0.6331，那个差距
是以**闪烁**的形式肉眼可见的。+0.009 只是它的一个小零头，**很可能根本看不出来**。

受控对比的做法是现成的：`scripts/predictor_precision.py` 的 `--bundle` 可以给多次，在
**同一条片子、同一几何、同一 seed** 上并排评多个打分器，这样换片子的混淆被彻底去掉。
需要先用 `scripts/export_predictor.py` 从 checkpoint 导出 bundle。

### 权重是**相干**地在动，不是随机游走

| step | 实测 `proj_q` RMS | 若随机游走 $\propto\sqrt{t}$ | 若相干 $\propto t$ |
|---|---|---|---|
| 25 | 5.81e-4 | 5.81e-4 | 5.81e-4 |
| 50 | 1.15e-3 | 8.21e-4 | 1.16e-3 |
| 75 | 1.61e-3 | 1.01e-3 | 1.74e-3 |
| 100 | 2.03e-3 | 1.16e-3 | 2.32e-3 |

**线性，不是根号**。相干比例约 **20%**（2.03e-3 相对 100 步 × 1e-4 的全相干上界），和
`update_align` 的量级一致。这和 lr 1e-2 那一臂正好相反，那一臂是 165 倍的随机游走
（§2.6）。按这个速率，第 400 步落在 8.1e-3，从下方接近 Veda1 训练后的 1.15e-2——
**不是冲过去，是走到**。

### 但被记录的损失在两个几何上变差了，而这暴露了一个更深的规范

| 几何 | slack 起点 | 第 101~104 步 | 斜率 / 100 步 | t | `logit_std` 斜率 |
|---|---|---|---|---|---|
| 16:9 | 0.0838 | 0.1020 | +0.01897 | **12.28** | +13.96 (t +0.9) |
| 9:16 | 0.0845 | 0.0992 | +0.01785 | **11.23** | +0.51 (t +0.1) |
| 4:3 | 0.0730 | 0.0857 | +0.01399 | 8.04 | −2.19 (t −0.6) |
| 1:1 | 0.0791 | 0.0893 | +0.01296 | 7.22 | −1.23 (t −0.1) |

其中 $\text{slack} = \texttt{retained} + \texttt{transport} \ge 0$，是**放松的代价**：
软 policy 不可能比硬 top-k 留下更多质量。账是闭合的：16:9 的 `retained` 涨 0.0115、
slack 涨 0.0190，于是 `transport` 变差 0.0075，实测 +0.00708。

而 `logit_std` **没有趋势**（t −0.6 ~ +0.9），所以这不是整体尺度跑飞，是**切点附近的
分布形状在被重塑**。

原因是我把规范认小了。**top-k 对逐行的任意严格单调映射都不变**，不只是正仿射。
`transport_loss` 只固定了仿射这个子群，剩下的非线性单调自由度**仍然是 kernel 看不见的
规范**，而它的梯度恰好集中在切点——那正是重塑最便宜的地方。实测，五个保序映射：

| 保序映射 | 排序不变 | **hard** | soft（std 宽度） | soft（rank 宽度） |
|---|---|---|---|---|
| identity | ✓ | **0.9141** | 0.8409 | 0.8044 |
| 立方（锐化尾部） | ✓ | **0.9141** | 0.7388 | 0.5700 |
| 立方根（压缩尾部） | ✓ | **0.9141** | 0.6322 | 0.8321 |
| tanh | ✓ | **0.9141** | 0.7249 | 0.8452 |
| asinh | ✓ | **0.9141** | 0.6857 | 0.8404 |

硬值**逐位恒为 0.9141**，软值在 0.632 ~ 0.841 之间摆——决策内容完全相同。

**而且这是方法的下界，不是一个能修的 bug**：唯一对单调映射不变的统计量是**秩**，而秩的
梯度几乎处处为零。把 sigmoid 宽度改成由切点附近的次序统计量定义，在四个重塑里改善了
三个却在「锐化尾部」上更差（0.570），所以不是干净的赢。

**可操作的结论**：判断训练一律看 `retained`（硬选择），**永远不要看记录下来的损失**——
损失是一个放松，而它的 slack 本身就是一个自由参数。§2.5 加 `retained` 这件事因此是
承重的，不是装饰。

## 2.8 为什么是 mass 而不是 mean，以及零阶层面上和 VSA / Sol 的关系

这一节回答三个被问到的问题，每条都有实测。

### mass 对 mean：两者的差**逐位就是** `log B_j`

按定义 `mass_ij = Σ_{u∈i,v∈j} e^{s_uv}`、`mean_ij = mass_ij / (B_i B_j)`，所以

```
log mass = log mean + log B_i + log B_j
```

对固定的 query tile `i`，`log B_i` 是跨 `j` 的常数、不影响排序。
**所以「按 mass 排」和「按 mean 排」的差，逐位就是 `log B_j`**——`count_term`
不是一个附加特征，它**就是**这个选择。两件事是同一个决定说了两遍。

mass 是对的，因为**丢掉一个块所摧毁的量在它的 key 上可加**：OT 可达值
`F(S) = log Σ_{v∈S} e^s` 是一个**和**。一个只有 8 个高分 key 的 tile 均值很高，
携带的质量只有同均值满 tile 的 1/16。

实测（360 tile、预算 36、真实行数 8~128、std(log rows) 0.495）：

| 按什么排 top-k | 与 mass 选择的重叠 | 保住的真实块质量 | 所选 tile 平均行数 |
|---|---|---|---|
| **mass** | — | **0.1341** | 127.9 |
| mean | **0.389**（14/36） | 0.0842 | 75.3 |

两个集合只重叠 38.9%，mass 多保住 **59%（相对）** 的质量。机制在最后一列：
**mean 系统性偏向小 tile**。

三个候选目标是**同一个轴**上的三点：**max**（Veda1，极值统计量 → 闪烁）、
**mean**（把行数归一化掉，对 `log B_j` 盲）、**mass**（OT 可达值本身）。

### 推导链逐项验证（D=128、每 tile 128 行）

`log Σ e^s = log M + log E[e^s]`，后项是经验分布的累积量生成函数在 1 处取值，
`= μ + σ²/2 + κ₃/6 + …`：

| 量 | 直接计算 | 闭式 | 相对误差 |
|---|---|---|---|
| 块对上 s 的**均值** vs `(Q̄·K̄)/√D` | 0.075099 | 0.075099 | **9.9e-08** |
| 块对上 s 的**方差** vs `tr(C_q C_k)/D − μ²` | 0.245055 | 0.245055 | **6.1e-08** |
| 同上**只取对角** `Σ_d E[q_d²]Var(k_d)/D` | 0.245055 | 0.188649 | 2.3e-01 |

**第一项是精确的，不是近似**：内积双线性，所以块对上的均值恰好分解成两个池化均值的内积。
这就是「均值池化 QK」不是启发式的原因——它是精确的一阶矩，**唯一的近似是截断级数**。

| 估计 | log 块质量 | 误差 | 代价 |
|---|---|---|---|
| 真值 | 9.902772 | — | O(B²D) |
| 零阶（log 计数 + 池化 QK） | 9.779160 | +0.1236 | 已有 |
| + **精确**二阶累积量 | 9.901687 | **+0.0011** | rank D²，付不起 |
| + **对角**二阶累积量 | 9.873484 | +0.0293 | rank r ≤ D，r=8 够 |

**一个必须讲清楚的反直觉点**：精确二阶项作为 log 质量的**点估计**比零阶好 112 倍、
比对角版好 27 倍，但在**选块**上实测**更差**（ρ=5% 补回 38.8% 对 46.0%，§2）。
这不矛盾：**排序只在乎随 j 变化的那部分误差**，跨 j 近似恒定的分量对排序完全免费。
「更准的点估计」和「更好的排序」是两件事，我们要的是后者。

### 零阶层面上，VSA、未训练的 Veda1、Veda2 的第一项是**同一个东西**

先把两个轴分开，这个问题容易把它们混在一起：

| 轴 | 问的是 | 取值 |
|---|---|---|
| **目标** | 按什么排 | max / mean / **mass** |
| **估计量** | 怎么便宜地算出来 | 池化 QK + 哪些修正项 |

在估计量的零阶上：

- **VSA**：把 cube 均值池化，然后**对池化表示做一次注意力** → 分数是 `q̄_i·k̄_j/√D`；
- **未训练的 Veda1**：`q̄_i·k̄_j/√D`（`embed` 的残差）；
- **Veda2 的第一项**：`q̄_i·k̄_j/√D`。

**三者完全相同。** 所以差别**不在零阶**，而在后面加了哪些项。

而这里有一个对 VSA 的精确判断：**均值池化把行数归一化掉了，所以 VSA 的粗粒度分数
排的是 mean 而不是 mass。** VSA 没有因此受损，是因为它**把 cube 固定成 4×4×4 并要求
latent 维度整除 4**——这时 `B_j` 是常数，那一项恒等地消失。我们不能这么做：
几何本身是请求参数（4 种纵横比 × 3 种时长），tile 是 ragged 的，
**所以我们必须把 `log B_j` 加回来**。

> 一句话：**VSA 用约束几何绕开这一项，我们用加一项来修它。** 这是两种合法的做法，
> 但在几何不能被约束的场景里只有后者可用。

**Sol-Attn 完全在另一个轴上**：它是一条**预算分配规则**（`μ+βσ` 决定每行留多少），
作用在已有的分数之上，不是块重要度的估计量。所以零阶上它没有可比的东西——它假设分数已经
有了。我们的实测结论是：**打分器准确度是瓶颈（18~43%）时，那个轴不划算**。

**训练过的 Veda1** 形式上是超集（`[mean|max|min]` 上的可学习双线性），
但它的训练目标是 **max**，也就是目标轴上选错了——那正是闪烁的来源。

## 2.9 计数项的 layout 依赖：全 12 个几何的实测（P2-5 / 附录 F.1）

纯静态计算，**零 GPU**：对 `plans/released/` 里全部 12 张方案表，逐 (几何, tile 形状) 算
`count_term_leverage`，再按**该形状在 50 层 × 56 头里实际占的比例**加权。

| 几何 | 头加权 `std(log B)` | 头加权 leverage |
|---|---|---|
| 16x9_t37 | 0.3487 | **8.9%** |
| 9x16_t37 | 0.3487 | **8.9%** |
| 16x9_t102 | 0.2018 | **5.2%** |
| 9x16_t102 | 0.2018 | **5.2%** |
| 1x1_t37 | 0.1708 | **4.4%** |

### 先更正我自己写错的一个数字

我之前在文档和报告里引用的「16:9@37 的 `std(log B)` 是 0.664、leverage 17%」，
用的是 **`4x4x8` 这个形状，而它根本不在 16:9@37 的发布方案表里**
（那张表是 `8x4x4` / `2x8x8` / `4x8x4` / `8x8x2`）。
按**实际部署的形状**并按头加权，16:9@37 的 leverage 是 **8.9%**、`std(log B)` 是 **0.349**。
也就是说**我原来的数字高估了约 2 倍**，因为它取的是一个手挑的形状而不是实际在跑的那些。
结论的方向不变（16:9@37 仍然是 12 个几何里 leverage 最高的），但量级要改。

### P2-5 得到确认，而且比预期更干净

| 判定 | 结果 |
|---|---|
| padding 恰为 0 的 (几何, 形状) 组合 | **16 个** |
| 它们的 `std(log B)` 最大值 | **9.5e-07**（fp32 噪声，即恒等为零） |
| **每一个** tile 形状都全满的几何 | **`1x1_t72`、`4x3_t72`** |

所以在 `1x1@72` 和 `4x3@72` 上，**计数项的贡献精确为零**，不是「很小」。
这正是 P2-5 要的那条：tile 全满时该项恒等消失，与静态预测器一致。
而它同时说明一件对论文更重要的事:**`log B_j` 不是一个普适收益项，它是
ragged layout 的修正项**。12 个几何上头加权 leverage 从 **0.0% 到 8.9%**，跨度无穷大
（有两个精确为零）。任何「计数项值 22~36%」的表述都必须绑定到具体 layout。

### 为什么 t72 比 t37 和 t102 都干净

latent_t 72 恰好能被这批 tile 的时间维（2/4/8）整除，而 37 和 102 都不能
（37 是质数，102 = 2×3×17）。所以时间轴在 t72 上不补齐，只剩空间轴，而 1:1 和 4:3 的
`latent_h/w` 也刚好整除。**这是一个纯整除性质，可以在选几何之前就算出来**,
`count_term_leverage` 的存在意义就是这个。

## 2.10 误差分解：高稀疏下路由只占 16%，长尾占 84%（P0-4 配套分析）

零 GPU，从盘上已有的 67200 行消融记录直接算（16:9@37、2 条 holdout clip、50 层 × 56 头 ×
3 个密度）。把注意力输出的相对误差拆成两块：

- **长尾**：质量 oracle 自己的误差（`A|0`）。即使路由**完美**也要付，因为预算有限；
- **路由代价**：代理的误差减去它（`R1_topk|0 − A|0`）。即「漏掉了重 tile」。

| 密度 | 长尾（oracle 自身误差） | 代理总误差 | 路由代价 | **路由占比** |
|---|---|---|---|---|
| 5% | 0.28852 | 0.34775 | 0.05923 | **16.3%** |
| 10% | 0.16135 | 0.22109 | 0.05974 | **25.2%** |
| 20% | 0.07716 | 0.13016 | 0.05300 | **36.7%** |

换成真正的下界（输出误差 oracle 而不是质量 oracle）结论不变：17.5% / 27.3% / 39.2%。

### 两个读法，第二个对我们自己不利

**路由代价在绝对值上几乎不随密度变化**（0.053 到 0.060），而长尾随预算增大迅速缩小
（0.289 → 0.077）。所以**路由占比随密度上升**：5% 时 16%，20% 时 37%。

于是在我们真正关心的 **95% 稀疏**上：**误差的 84% 是不可约的长尾**，只有 16% 来自路由。

这**部分削弱了我自己反复强调的那条**（「瓶颈是打分器准确度」）。那条论断来自
「补回 oracle 差距的比例」这个口径,在**选块质量**的度量上打分器确实是瓶颈。
但换成**注意力输出误差**的口径，高稀疏下主导项是长尾而不是路由。两个口径都对，
量的是不同的东西，而论文必须把这件事说清楚，否则就是挑有利的那个口径。

### 它同时让「补偿不划算」这个结论更值得注意，而不是更不值得

补偿针对的恰恰是**长尾**,也就是 95% 稀疏下占 84% 的那一块。所以
「零阶补偿在等 FLOP 下是平局」这个实测结果是在攻击**主导项**的情况下得到的平局，
这比攻击次要项得到平局更强。

但它也说明为什么 SLA 和 VSA 都带第二条路径：**在高稀疏下那是误差的大头**。
所以 §5.5 列的那个空洞（「要不要加第二条便宜路径」没答案）比我原先判断的更要紧,
零阶补偿不划算**不能**外推成「所有补偿都不划算」，因为更强的补偿攻击的是同一个
占 84% 的目标。

## 2.11 P0-1 第一个结果：PSNR 看不见人眼看见的那个差别

12 条 demo caption（PE 后原文）、16:9@37、95% 稀疏目标、同 seed 同 prompt 同调度，
四路对 dense 的逐帧 PSNR / SSIM，bootstrap over clips 给 95% 区间：

| 臂 | 实际稀疏度 | PSNR dB | 95% CI | SSIM | 95% CI |
|---|---|---|---|---|---|
| Sol-Attn | **98.6%** | 14.706 | [13.910, 15.684] | 0.650 | [0.614, 0.693] |
| Veda2 (r16) | 95.0% | 14.471 | [13.619, 15.455] | 0.650 | [0.614, 0.693] |
| Veda1 (step600) | 95.0% | 14.257 | [13.192, 15.453] | 0.644 | [0.606, 0.689] |

（Sol 的密度是实测的，不是配置的:`tau` 是阈值不是预算，tau 1.2 在真实激活上给出
0.0131~0.0146 的路由比例，区间 [0.0000, 0.0507] 跨层跨头差 500 倍。重标定到 5% 的那一轮
在队列里。）

### 三件事，第一件对我们不利

**一、三路在统计上无法区分。** 区间几乎完全重叠。Veda2 比 Veda1 高 0.21 dB、方向与路由
指标一致，但 n=11 下不显著。计划自己预见了这个风险（「VBench 区分度低常见」），这里是
PSNR 也一样。**不能拿这张表声称 Veda2 更好。**

**二、PSNR 的绝对值很低（14.5 dB）**，说明 95% 稀疏对任何 router 都是一个大扰动,
它改变的是像素的大头，不是细节。

**三、这是最重要的一条：人眼看见的那个差别，PSNR 结构上看不见。**
之前的人工确认是「Veda1 全部 5 条都闪烁，Veda2 没有」,而**闪烁是时间维的，
PSNR 和 SSIM 是逐帧的**。一个每帧都偏一点但偏得稳定的输出，和一个每帧偏得同样多但
帧间跳动的输出，有同样的 PSNR。所以：

> **PSNR / SSIM 不是能判这件事的指标**，尽管它是这个领域的标配。
> 这把 §7 待办里的 **mask churn 指标**（相邻去噪步之间、时间上相邻 query tile 之间所选
> 集合的重叠）从「加分项」提到了**必要项**,它是唯一能量化那个人眼差别的量。
> 论文里 PSNR 表必须和它并列，否则就是用一个看不见目标的尺子量目标。

### Sol 的那一行需要特别说明

它在 **3.5 倍更高的稀疏度**下拿到了和 Veda2 持平的 PSNR。当时写的是「如果重标定到同
密度之后它仍然持平或更好，那是**支持补偿**的证据」——**已经标定并重跑了，答案是更好**
（t37 上 PSNR +0.816 赢 11/11、SSIM +0.0229 赢 10/11，见 2.14），和 §2.10 的分解一致
（95% 稀疏下误差的 84% 是长尾，而补偿正是针对长尾）。

但这一行的两个混淆变量**仍然没拆开**，所以它还不是「补偿有用」的证据：
**块几何**（Sol 用原始序列顺序的 64 连续 token，我们用搜索出的 3D tile）和
**预算类型**（动态阈值每行自适应块数，对我们的固定每头 top-k）。再加上第三个：
**成本**，同密度下 Sol 的注意力是 Veda2 的 2.11 倍。三个都没拆开之前，这一行说明的是
「Sol 这个系统在 t37 同密度下更好」，不是「补偿这一项更好」。

### 射程与未做的部分

- **两臂用的是同一个块几何**（我们的 128-token 3D tile），所以这满足 E1 的第一条要求,
  「补偿值不值得」这个问题是在**一个几何内部**回答的，没有粒度混淆。
- **未做**：在 64-token 块上重做一遍，确认结论不依赖块大小。外部对比页的 Sol 用的是
  64 连续块，所以要把结论外推到它，还需要这一步。
- **未做**：E4 端到端。注意力只占 t102 一步的 72%、t37 的 48%，所以这里的误差差异
  在端到端会被稀释，必须另测。

## 2.14 撤回 2.12 的 Sol 比较：那一轮 Sol 只拿到 1.67% 预算（P0-1 更正）

2.12 写的是「在原始时长上 Veda2 的 SSIM 显著优于 Sol」。**这个结论不成立，现在撤回。**

原因是我自己配的实验不公平。Sol-Attn 的路由是**阈值**式的
（`mean + tau*std`，见 `miowtion/kernels/sol.py`），不是预算式的：tau 是一个阈值，
它最终路由多少块是**激活的性质**，不是配置的性质。我在两轮 demo 里都填了
`sol_tau: 1.2`，而实测：

| 轮次 | 几何 | tau | Sol 实测密度 | Veda 预算 |
|---|---|---|---|---|
| 第一轮 | 16:9@37 | 1.2 | 约 1.4% | 5% |
| 第二轮 | 16:9@102 | 1.2 | **1.67%** | 5% |

也就是 2.12 那张表是拿 **5% 预算的 Veda2** 和 **1.67% 预算的 Sol** 在比，Sol 少了
三倍预算。这个偏差方向恰好对我们有利，所以它必须被当成错误处理，而不是当成结果。

### 标定到同密度之后，t37 上结论反过来了

把 tau 标到 0.7（16:9@37 实测 4.82%，是最接近 Veda 那 5% 的工作点）重跑，11 条 clip
全部配对：

|---|---|---|---|---|---|

| PSNR | Sol(4.82%) − Veda2 | 11 | **+0.816** | [+0.478, +1.226] | **11/11** * |
| SSIM | Sol(4.82%) − Veda1 | 11 | **+0.0293** | [+0.0127, +0.0467] | 9/11 * |
| SSIM | Sol(4.82%) − Veda2 | 11 | **+0.0229** | [+0.0102, +0.0374] | 10/11 * |
| PSNR | Sol(1.4%) − Sol(4.82%) | 11 | −0.581 | [−0.959, −0.180] | 2/11 * |
| SSIM | Sol(1.4%) − Sol(4.82%) | 11 | −0.0228 | [−0.0356, −0.0099] | 2/11 * |

（`*` = 配对区间不含零。最后两行量的是标定本身值多少：错配那三倍预算在 SSIM 上就是

### 但「同密度」不是「同成本」，而这正是我们对外部对比页提的那条反对

同一批 clip 上实测的耗时（16:9@37，去掉第一条 clip 的 autotune）：

| 臂 | 密度 | 注意力 | 整个 denoise | 对 dense 的加速 |
|---|---|---|---|---|
| dense | 100% | 46.3 s | 96.6 s | — |
| Sol tau 0.7 | 4.82% | **20.9 s** | 69.7 s | 1.39× |
| Veda2 | 5% | **9.9 s** | 58.5 s | **1.65×** |

**同密度下 Sol 的注意力要花 Veda2 的 2.11 倍。** 原因是结构性的：Sol 除了路由出来的
块，还要为每个未路由块算质心补偿（`kc = sum(k)/block_len`、`vc = sum(v)`），这部分的
成本随**全部**块数走而不是随保留块数走。所以上面那张质量表的正确读法是：

> 用 2.11 倍的注意力时间，Sol 换到 +0.0229 SSIM。

这和我们在 `REBUTTAL.html` 里对外部对比页提的反对是**同一条**：他们把 `Sol top-k 10%`
（没有补偿、106 ms）的收益记在补偿头上，而真正带补偿的那一路标着「not timed」。
同一把尺子必须量在自己身上——所以等密度的这张表不能当结论，等时间的那张才能。

### 因此新增 E5：等时间曲线（已排队）

`configs/infer_demo12_16x9_veda2_d{008,010,012}.yaml`，把 Veda2 的预算一路加到它的
注意力耗时追上 Sol 的 20.9 s，读出同一批 11 条 clip 的质量。两种结局都要照原样写进来：

- 如果 Veda2 在同时间下追回 0.0229 SSIM：那么 Sol 的优势是**预算优势而不是补偿优势**，
  和 P0-4 的天花板（补偿只占 13.9%，多选块占 28.8~32.4%，2.06~2.32×）一致。
- 如果追不回：那么补偿买到了我们用 tile 买不到的东西，**这要作为局限写进论文**，
  而且 §5「为什么零阶补偿不进 Veda2」需要重写——那一节现在的依据是等成本分析，
  如果等时间的像素不支持它，等成本分析就不足以支撑那个设计决定。

### t102 的同密度重跑回来了：同向，不是反向

tau 0.7 在原始时长上实测 **5.56%**（对 Veda 的 5%，Sol 多拿 11% 预算，这一点要记上），
10 条 clip 配对：

| SSIM | Sol(5.56%) − Veda2 | **+0.0179** | [+0.0041, +0.0320] | **8/10** * |

**所以 t102 上 Sol 也显著更好，方向和 t37 相同。** 2.12 原先那个「Veda2 更优」不是只需

### 而成本的倍数随序列长度**变大**，这是对补偿不利的方向

| 几何 | dense 注意力 | Sol 注意力（同密度） | Veda2 注意力 | 倍数 | Sol step 加速 | Veda2 step 加速 |
|---|---|---|---|---|---|---|
| 16:9@37 | 46.3 s | 20.9 s | **9.9 s** | **2.11×** | 1.39× | **1.65×** |
| 16:9@102 | 347.4 s | 109.4 s | **38.3 s** | **2.86×** | 1.97× | **2.81×** |

倍数从 2.11 升到 2.86，和「质心补偿的成本随**全部**块数走、不随保留块数走」这个预测
一致：序列越长、块越多，补偿这笔固定开销在总成本里占比越大。**也就是在稀疏本该最划算的
长序列上，补偿最贵。**

于是等时间的余量在 t102 上是 **2.86 倍**而不是 t37 的 2.11 倍。E5 只排在 t37，所以补了
E5b（`configs/infer_demo12_orig_16x9_t102_veda2_d{010,015}.yaml`，10% 和 15% 预算），
在 t102 上读出 Veda2 的质量-时间曲线。这才是决定性的那一格，因为 t37 的注意力只占一步
的 48%，而 t102 占 72%。

**现在还不能说的话：** 「等时间下 Veda2 更好」。E5 / E5b 没回来之前，我们手上成立的是
「同密度下 Sol 更好，但贵 2.11~2.86 倍」。P0-4 的等成本上界（补偿 13.9%，多选块
28.8~32.4%，2.06~2.32×）**预测**余量足够补回来，但那是在注意力输出误差口径上算的，
不是像素，而 2.11 节已经证明这两个口径会给出不同的结论。

### 没有受影响的那一条

2.12 里 `Veda1 − Veda2` 的配对结论**不受影响**：两臂都是 5% 预算、同一个 kernel、
同一个几何，差的只有打分器。t102 上 SSIM +0.0076 [+0.0006, +0.0136]、9/10 条，
仍然成立；t37 上 +0.0064 [−0.0012, +0.0136]、8/11，仍然不显著。

## 2.15 E0 量纲核对有结论：`diag` 是官方那组数字的工作点，剩下的是常数

计划 §3.5 的 E0。ComfyUI 文档给的是 tau 1.0 约 16%、1.5 约 7%、2.0 约 2.7%，我们实测差
六倍。假设是 `thresh_type`：上游默认 `diag`、ComfyUI 节点取默认值，而我们的 wrapper 默认
`exact`（全协方差、阈值更紧）。一次运行扫完整条曲线（50 次调用，真实 H3 激活，16:9@37）：

| tau | 0.5 | 0.7 | 1.0 | 1.3 | 1.5 | 1.7 | 2.0 | 2.5 |
|---|---|---|---|---|---|---|---|---|
| `diag` | .0946 | .0701 | **.0430** | .0254 | **.0176** | .0122 | **.0072** | .0032 |
| `exact` | .0777 | .0517 | **.0260** | .0121 | **.0071** | .0041 | **.0019** | .0007 |

**假设只对了一半，而对的那一半很干净。** `diag` 没有复现 16/7/2.7，但：

| tau | 官方 | `diag` | 倍数 | `exact` | 倍数 |
|---|---|---|---|---|---|
| 1.0 | 16% | 4.30% | **3.72×** | 2.60% | 6.15× |
| 1.5 | 7% | 1.76% | **3.98×** | 0.71% | 9.86× |
| 2.0 | 2.7% | 0.72% | **3.75×** | 0.19% | 14.21× |

**`diag` 的偏差是个常数**（3.72 / 3.98 / 3.75），而 `exact` 的偏差一路从 6.15 放大到
14.21。曲线形状也印证：相邻点之比官方是 2.29 / 2.59，`diag` 是 2.44 / 2.44，
`exact` 是 3.66 / 3.74。

### 读法：两边都没错，而该修的那个是我们

1. **`diag` 是官方那组数字描述的工作点。** 形状对上了，只差一个常数。
2. **那个常数不是谁的错。** 阈值是 `mean + tau*std`，所以给定 tau 的密度取决于**块分数
   分布右尾的形状**，那是模型的性质。他们在自己的模型上量，我们在 H3 上量，得到相差
   3.8 倍的常数是预期行为。**tau 不可跨模型迁移**——这比「某一方算错了」更有用，而且它是
   「阈值不是预算」（2.14）在跨模型方向上的同一条结论。
3. **我们之前所有 Sol 臂跑的是 `exact`，那是错的臂。** 不是因为 `exact` 不对，而是因为
   Sol 本来被设计、被文档、被 ComfyUI 节点默认跑在 `diag` 上。按密度做了经验标定之后
   **预算是公平的**，但同密度下 `diag` 和 `exact` 选的是**不同的块**，质量可以不同。
   所以要补一个 `diag` 臂（E0b，tau 0.9 按上表读出约 5%，已排队）。

### 对第五、六节的影响

`REBUTTAL.html` 原先写「结论未出之前，本文与他们表格的任何数值对比都不成立」。现在成立了,
但要带上这句限定：**他们表里的 tau 值在 H3 上对应的密度要除以约 3.8**，不能直接搬。
他们那张表里 `Sol τ1.3 +256` 这一行，在他们的模型上是官方口径的某个密度，在我们这里
tau 1.3 的 `diag` 密度是 2.54%——所以**跨模型比较只能按密度对齐，不能按 tau 对齐**。

## 2.16 E5 等时间曲线：同成本下补偿输给多选块，而且还没走到等成本就输了

2.14 留下的那一格。同密度下 Sol 在两个几何上都显著更好，但它的注意力贵
2.11×（t37）到 2.86×（t102）。于是问题是：**把那笔钱改成买 tile，能不能买回同样的质量。**

`configs/infer_demo12_16x9_veda2_d{008,010}.yaml`，同一批 11 条 clip、同 seed、同 prompt、
同调度、同 kernel，只动预算：

| dense | 100% | 46.33 s | 222% | — | — |
| Veda2 | 5% | **9.90 s** | 47% | 14.471 | 0.650 |

| **Veda2** | **10%** | **12.03 s** | **58%** | **14.953** | **0.669** |

| Sol − Veda2@5% | SSIM | +0.0229 | [+0.0102, +0.0374] | 10/11 | **是** |
| Sol − Veda2@8% | SSIM | +0.0117 | [−0.0012, +0.0266] | 6/11 | 否 |

**在 10% 密度上，两个指标都已经不显著了，而那只花了 Sol 注意力的 58%。**

### 把成本写成比值

- 买「两倍的 tile」（5% → 10%）：注意力 **1.22×**
- 买「补偿」（Veda2@5% → Sol@4.82%）：注意力 **2.11×**
- 同样的质量，**tile 便宜 1.73 倍**

而且这是个**下界**：10% 时差距已经统计上消失，等时间的交点要到 **30.8% 密度**
（注意力 = 7.77 s 固定 + 42.6 s×密度，解 20.87 s）。d020 / d030 两级在跑，预期会越过去。

### 为什么这条比 P0-4 的上界更有说服力

P0-4 的等成本结论（补偿 13.9%，多选块 28.8~32.4%，**2.06~2.32×**）是在**注意力输出误差**
口径上算的。这里的 **1.73×** 是在**像素**上量的，而 §2.11 已经证明这两个口径会给出不同的
结论（PSNR 看不见人眼看见的差别）。两个独立口径给出同一个方向和同一个量级，
**这比任何一个单独成立都强**。

### 成立的和不成立的

**成立：** 在固定的注意力预算下，把钱花在多选块比花在零阶补偿划算，t37 上至少 1.73 倍。
这支持 §5「零阶补偿不进 Veda2」这个设计决定——而在拿到这条之前，那个决定只有
等成本的误差分析支撑，不足以回答像素。

**不成立（还）：**

- **这不是说补偿没用。** 同密度下它确实显著更好（2.14），P0-4 也说它拿到了完美质量估计
  的 90%。它只是**买贵了**。
- **t102 还没有这条曲线。** 那里 Sol 的倍数是 2.86× 而不是 2.11×，余量更大，所以预期
  同向且更强，但 E5b（10% / 15%）没回来之前不要替它下结论。
- **「1.73×」是在我们自己的块几何上。** Sol 在 64 连续块上，E1@64 和 E1 连续块两个
  单变量消融在跑。
- **补偿还没在我们自己的路径上跑过。** E4（`veda_comp`）才是「只差补偿」的那一格；
  上表的 Sol 臂同时还差块几何和预算类型。

## 2.17 S-2：补偿的收益在 oracle 上**没有**消失，计划里那个理论预测是错的

`EXPERIMENT_PLAN.md` 的 S-2 写了一个理论预测：**「router 越接近 oracle，补偿收益越小」**，
理由看起来很硬——误差恒等式里补偿把每个被丢掉的项换成它估计量的残差，所以一个不漏选
重要 tile 的 router 应该没什么可修的。并且写明「若受控实验在 mass oracle 选择下仍测到
可观收益，再讨论 Observation 2 的措辞」。

这条可以**不花 GPU** 就回答：`ablate_sol.py` 写出的记录里，每个
(clip, step, layer, head, density) 都已经带了 16 个 mask 各自的 `errors[mask|c]`
（c = 0, 1, 2）和 `recall_vs_mass[mask]`。`scripts/compensation_vs_router.py` 把这两列
对起来，11200 行/密度：

| 5% 密度，router 按 recall 排序 | recall vs mass | ε(c=0) | ε(c=1) | 收益 | 帮到的行 |
|---|---|---|---|---|---|
| `R3_sigma_a2`（最差） | 0.4893 | 0.5084 | 0.3570 | **+22.3%** | 98.9% |
| `R2_zscore` | 0.5692 | 0.3878 | 0.3150 | +14.2% | 98.5% |
| `proxy_topk`（mean q·k） | 0.5842 | 0.3558 | 0.3007 | +12.3% | 98.3% |
| `proxy_diag_topk`（Veda2 对角） | 0.6964 | 0.3239 | 0.2768 | +11.9% | 98.3% |
| `oracle_threshold` | 0.7363 | 0.3271 | 0.2355 | **+19.6%** | 99.4% |
| `oracle_topk` / `Omega0` | 0.8689 | 0.2862 | 0.2366 | +13.7% | 98.7% |
| **`A`（mass oracle，定义上完美）** | **1.0000** | 0.2907 | 0.2427 | **+13.1%** | **98.6%** |

**预测被否掉，而且是两重否掉：**

1. **收益在 recall = 1.0 上仍有 13.1%**，不是零。所以「好 router 没什么可修」不成立。
2. **关系甚至不单调。** `oracle_threshold`（recall 0.736）的收益 19.6% 比它两边的
   router 都高；`Mx`（0.646）的 14.6% 高于 `proxy_logb`（0.676）的 11.5%。
   用 recall 单独预测补偿收益是预测不出来的。

而且 **补偿在每一个 router 上都帮到了 98~99% 的行**，三个密度都是。这不是边缘效应。

### 为什么收益活了下来：它修的不是选择，是长尾

和 2.10 对上了。那一节量到：**5% 稀疏下路由决定只占注意力输出误差的 16.3%，长尾占 84%。**
即使 router 完美，95% 的 tile 还是被丢掉了，它们的总质量不为零，而质心估计把其中一部分
捞了回来。**补偿作用在长尾上，所以一个完美的 router 几乎不减少它的工作量。**

两条结论互相加强而不是互相矛盾：2.10 说误差的主体是长尾，S-2 说针对长尾的手段在任何
router 下都有效。

### 这不改变成本结论，但它改变论证的形状

**要删掉的论证：**「补偿只能修复漏选，所以对好 router 没用」。那是错的，而且正文里不该
出现（已核对：论文的 Observation 2 并没有用这条推理，它从头到尾只讲性价比，所以正文
安全；被否掉的是计划里的那个预测）。

**剩下的、也是唯一的论证：** 补偿**买贵了**。2.16 在像素上量到 tile 便宜 **1.73×**，
P0-4 在误差上量到等成本 **2.06~2.32×**。S-2 恰好说明为什么那个价格值得认真对待——
补偿确实普遍有效，所以「它没用」是站不住的，能站住的只有「同样的钱买 tile 更划算」。

论文的 Observation 2 因此补了一句：**在 oracle 选择下补偿仍然降低误差**。这是主动把对自己
最不利的读法写进去，省得审稿人自己发现。

## 2.18 S-5：我们工作点上的注意力时间有 79% 不是 kernel

S-5 要求「单独报 router + gather（token permutation）开销」。E5 的预算阶梯顺带把它解出来了，
不需要额外实验：同一批 11 条 clip、同几何，只动预算，于是耗时随密度的变化就是 kernel 的
那一部分，截距就是密度无关的那一部分。

16:9@37，三级最小二乘（每级 10 条 clip 的均值，去掉首条的 autotune）：

```
注意力(d) = 7.770 s + 42.61 s × 密度
```

**残差是 ±0.001 s。** 三个点拟两个参数当然容易，但残差小到测量精度以内，说明这不是粗略
拟合而是一个干净的分解。

| 密度 | 实测 | 固定部分 | 占比 | 随密度的部分 |
|---|---|---|---|---|
| 5% | 9.90 s | 7.77 s | **78.5%** | 2.13 s |
| 8% | 11.18 s | 7.77 s | 69.5% | 3.41 s |
| 10% | 12.03 s | 7.77 s | 64.6% | 4.26 s |

### 三个推论

**一、稀疏 kernel 不是我们工作点上的瓶颈。** 5% 密度下真正做块稀疏注意力的只有 2.13 s，
剩下 7.77 s 是打分器前向、池化、以及把 q/k/v/out 在 tile 序和 packed 序之间搬来搬去。
**最高杠杆的优化在那 79% 上，不在 kernel 上。**

**二、这解释了为什么 E5 的阶梯那么便宜。** 5% → 10% 预算翻倍，kernel 部分也翻倍
（2.13 → 4.26 s），但它只占五分之一，所以总时间只涨 1.22×。**固定开销越大，多买 tile
就越划算**——2.16 那个 1.73× 的一部分来源就在这里，而它是实现的性质，不是方法的性质。
换一个开销更低的实现，那个倍数会变小。这一点必须在论文里说明，不能当成方法的固有优势。

**三、外部对比页在这一点上是对的。** 它观察到「124 帧时 Veda 路径有 host 侧 stall，
GPU 1/3 空闲」。我们独立量到一个很大的密度无关开销，和那个观察一致。
S-5 原本的建议（用 CUDA graphs / 去掉同步把 host 开销消掉，再做端到端对比）因此是
**有依据的**，不是对方的借口。

### 对已发布加速数字的影响

`docs/benchmark/` 里 t37 的「注意力加速 4.7×」是**受开销限制**的数字。它既低估了 kernel
本身能做到的，也高估了把开销修好之后用户还能再拿到多少——因为开销修好之后 dense 基线
不变而稀疏侧会更快，加速比会上升。两头都要说清楚：**报的是端到端实测，不是 kernel 上界。**

### t102 的分解回来了，预测对了，而且给出一个干净的标度

E5b 的 d010 跑完（10 条 clip 的去噪）之后就有了第二个点：t102 上 5% 是 38.29 s、
10% 是 53.77 s。

| 几何 | 固定开销 | 占 5% 时的 | kernel 斜率 | 等时间密度 |
|---|---|---|---|---|
| 16:9@37 | 7.77 s | **78.5%** | 42.6 s | 30.8% |
| 16:9@102 | **22.81 s** | **59.6%** | **309.6 s** | 28.0% |

序列长 2.76 倍（37 → 102）时：

- **固定开销涨 2.94×**，也就是约 **O(n)**。符合预期：主体是 gather / scatter 和池化，
  都是逐行的。
- **kernel 斜率涨 7.3×**，而 n² 是 7.6×，也就是约 **O(n²)**。注意力本来就是这样。

**所以固定开销的占比随序列变长而下降**（78.5% → 59.6%）。这个方向对方法有利：
开销问题最严重的地方（短序列）恰好是稀疏收益最小、我们也不主张加速的地方，
而在稀疏真正付钱的长序列上它最轻。2.12 的那张表说注意力占稠密一步的比例从 48% 升到 72%，
和这条是同一件事的两个侧面。

两个几何的**等时间密度非常接近**（30.8% 与 28.0%），尽管绝对耗时差一个数量级。

**顺带修正 E5b 的设计：** t102 的阶梯排的是 10% 和 15%，而交点在 28%,所以它和 t37 第一版
阶梯犯的是同一个错——够不到 Sol 的成本。但 t37 的经验是**差距在 10% 就已经抹平**，
远在交点之前，所以先看 d010 的质量再决定要不要加 25~30% 这一级，不要先烧 GPU。

## 2.20 E4：把补偿加到我们自己的路径上，视频显著**变差**——Sol 的优势不是补偿

计划 E4。这是整个项目里**唯一**一格「除了补偿什么都不差」的对比：同一个 tile 几何
（我们的 128-token 3D tile）、同一个训练好的打分器、同一个预算（5%）、同一个 FA4 kernel、
同一个 seed / prompt / 调度，`attention: [veda, veda_comp]` 一个进程跑两臂，连 adapter
merge 和 AdaLN 表都共享。

### 先看内置的一致性检查，它通过了

E4 的无补偿臂和早先那个独立的 `veda2` 臂是同配置同 seed，所以应该一模一样：

| 对比 | PSNR 差 | SSIM 差 | 赢 |
|---|---|---|---|
| `veda@e4` − `veda@veda2` | **+0.0000** [+0.0000, +0.0000] | **+0.0000** [+0.0000, +0.0000] | 0/11 |

**逐位相同。** 所以 plumbing 是干净的，两臂之间唯一的变量确实只有补偿。

### 结果：两个指标都显著变差

| 对比 | 均值差 | 95% CI | 赢 | 显著 |
|---|---|---|---|---|
| `veda` − `veda_comp`（PSNR） | **+0.424** | [+0.102, +0.781] | 7/11 | **是** |
| `veda` − `veda_comp`（**SSIM**） | **+0.0134** | [+0.0063, +0.0199] | **9/11** | **是** |

（差为正表示**不带补偿**的那一臂更好。）

而同一个补偿在**注意力输出误差**口径上是把我们这个 router 的误差降低 **11.9%** 的（S-2，
`proxy_diag_topk` 在 5% 密度）。**这是一次直接的口径反转：误差降了，像素变差了，而且两个
像素指标同向。**

### 不是实现差异：逐行对过 Sol 的源码

先排除「我们的 c=1 不等于 Sol 的补偿」这个解释。vendored 的
`third_party/Sana-solattn/techniques/sparse_backends/sol_attn/`：

| Sol 的源码 | 我们的 c=1 |
|---|---|
| `preprocess.py:52` `kc = sum(k)/block_len` | `k_mean = Σ_tile k / counts` |
| `preprocess.py:53` `vc = sum(v)` | `v_sum = Σ_tile v` |
| `fwd.py:96` `scores = q @ kc.T * scale` | `s_hat = q · k_meanᵀ · scale` |
| `fwd.py:122` `acc += p_hat @ vc` | `num += p_hat @ v_sum` |
| `fwd.py:129` `denom += p_hat * lengths` | `den += p_hat · counts` |

**形式完全一致。** 而我们的实现另外还：对着 `relative_errors` 的 c=1 测到 1e-6
（含部分填充 tile）、满密度下逐位惰性、稀疏时生效（三条单测）。所以这不是我们写错了。

### 因此：Sol 在同密度下赢的那部分，不是补偿贡献的

2.14 / 2.19 量到同密度下 Sol 显著更好（t37 SSIM +0.0229、t102 +0.0179）。那时候有三个
混淆变量没拆：**块几何**（64 连续 vs 我们的 128 3D tile）、**预算规则**（逐行阈值 vs
固定每头 top-k）、**补偿**。E4 把第三个拆出来了，答案是：

> **补偿这一项单独加上去是负贡献。** 所以 Sol 的优势只能来自块几何和/或预算规则。

这和外部对比页**自己的数据**是一致的：他们表里 `Sol top-k 10%`
**完全没有补偿**、成本更低（106 对 150 ms），就已经打平或打败了 Veda 的 learned router
（3.1 节量到那是总差距的 42.6~52.3%）。我们当时说「头条把块几何的贡献算到补偿账上」，
E4 现在从另一侧独立证实了同一件事——而且更强：**补偿的贡献不只是零，是负的。**

### 两个必须写明的限定

**一、成本不要用这个数。** `veda_comp` 的注意力是 33.1 s 对 `veda` 的 10.1 s（**3.3×**），
比 Sol 的 2.11× 还贵，因为我们的补偿是未融合的 torch 实现（一个 [rows, n_tiles] GEMM
加 exp 加两个 matvec），而 Sol 把 proxy reuse 融进了 online softmax。
**质量结论不受影响**（成本不改变输出），但**成本要引 Sol 的 2.11× / 2.86×，不要引 3.3×**。

**二、这是在 8 步 turbo 蒸馏的 H3 上测的。** 补偿按 Jensen 是**系统性低估**离散 tile 的
mass，也就是它往每一层每一步的输出里加了一个**有偏**的项。per-call 的 L2 看不见偏差沿
轨迹的累积，而少步蒸馏的调度对轨迹偏移更敏感。换成多步调度结果可能不同，这一条没测。

**所以「补偿有用吗」这个问题现在有三个不同口径的答案，必须一起报：**

| 口径 | 答案 |
|---|---|
| 注意力输出误差（per-call） | **有用**，降 11.9%，而且在 98~99% 的行上有用，连完美 oracle 下都有 13.1%（S-2） |
| 等成本的误差 | **不划算**，多选块 2.06~2.32×（P0-4） |
| **像素，端到端，只差补偿** | **负贡献**，PSNR −0.42 dB、SSIM −0.0134，都显著（E4） |

三个都是真的，量的是不同的东西。论文必须同时给，不能挑。

### 四、下一个杠杆：固定开销，不是算法

`注意力(d) = 7.77 s + 42.61 s × 密度`。把各部件单独计时（56 头一次做完，空闲卡）：

| 部件 | ms/call | ×400 |
|---|---|---|
| gather+pool q / k / v | 0.78 / 0.78 / 0.75 | 0.92 s |
| 打分器前向 | 0.338 | 0.14 s |
| `select_video_blocks` + `dense_block_mask` | 0.645 | 0.26 s |
| scatter out | 0.746 | 0.30 s |
| **非 kernel 合计** | **4.04** | **1.62 s** |
| FA4 kernel @5% | 6.007 | 2.40 s |

**部件只解释了 7.77 s 里的 1.62 s。** 剩下约 6 s 在结构里：已发布方案表每层用
**2 种形状 → 每层 2 个 head group**，于是每步 100 次分组启动而不是 50 次，每组只拿一半
的头，而这些算子在小尺寸下是延迟受限的。

**这是固定时间下最大的杠杆，而且不动算法、不动 tiling、不动打分器**：省下的每一秒都直接
换成密度。16 s 现在买到 20%，开销砍半就能买到约 29%。

## 2.23 churn：相邻 tile 之间一半的选择会换掉，而且越到后期越不稳

P2-1 / P2-3 的 churn。`offline_probe` 一度把它**算了、在日志里报了、然后没写进文件**
（`json.dump` 漏了那个 key，日志用的是局部变量），修掉之后第一次真正落盘。

`solattn.mask_churn` 量的是：一个 query tile 保留的 key 集合，**时间上相邻的下一个
query tile 还保留多少**（1.0 表示选择完全不动）。16:9@37，8 个去噪步：

| 形状 | 相邻 tile 的重叠 | 步间重叠 |
|---|---|---|
| `8x4x4` | **0.500** [0.383, 0.546] | 0.933 [0.844, 0.963] |
| `8x8x2` | **0.532** [0.518, 0.536] | 0.957 [0.903, 0.972] |

**时间相邻的两个 query tile 之间只有一半的选择共享，另一半整个换掉**；而同一个 tile
在相邻去噪步之间重叠 93~96%。**不稳定性在 tile 之间，不在步之间**，差一个数量级。

### 随去噪推进单调变差

```
step 0 -> 7:  相邻重叠 0.546 -> 0.383
              步间重叠 0.963 -> 0.844
```

两个都单调下降。后期 σ 小、注意力更尖锐，top-k 的边界竞争更激烈，微小扰动换掉更多块。
**要加稳定性约束的话，后期的步比前期值钱。**

### 和 2.22 的画面结论不矛盾

50% 的换血**不表现为周期性闪烁**（2.22 的周期性得分全在 1.0 附近），而是表现为
**整条生成轨迹走到别处**：选择变了一半，内容自然不同。两个观测说的是同一件事的两面。

## 2.24 `TILE_SIZE` 可配，S-4 的 2×2 终于补齐

我先前把「在 64-token 块上重做 E1」判为「75 处引用、14 个模块、import 时捕获，重构级，

## 2.25 tt 阶梯：时间跨度变 8 倍没有影响，预算变 4 倍完全解决

2.22 用周期性得分否掉了「tile 的时间跨度导致闪烁」，但那是个间接判据；而 2.23 的 churn
又量到**时间相邻的 query tile 之间有一半的选择换血**，所以这个假设值得一次直接的像素检验。
`--plan-dir` 的静默忽略修掉之后它才真正能跑（第一次跑出四个逐像素相同的视频）。

四个**均匀** plan，唯一的变量是一次路由决策覆盖多少帧，其余全部相同
（同 predictor、同 5% 预算、同 seed / prompt / 调度 / kernel）：

| plan | 形状 | 潜帧 | RGB 帧/决策 | 注意力 | 跟住 dense？ |
|---|---|---|---|---|---|
| `uniform_tt1` | `1x16x8` | 1 | **4** | **19.2 s** | ❌ |
| `uniform_tt2` | `2x8x8` | 2 | 8 | 15.0 s | ❌ |
| `uniform_tt4` | `4x8x4` | 4 | 16 | 未计时 | ❌ |
| `uniform_tt8` | `8x4x4` | 8 | **32** | — | ❌ |
| 已发布 @5% | 混合 | 2~8 | 8~32 | 9.9 s | ❌ |
| **已发布 @20%** | 混合 | 2~8 | 8~32 | **16.0 s** | **✅** |

`tt4` 前六次都报 rc=137（这台机器上模型建立阶段的突发分配间歇性触发 kill），
第七次成功——**而且它复用了第一次尝试留下的 latents**：那一次其实去噪完成了，

没有假设）。代价是 tt4 没有注意力耗时，因为那次只解码没去噪。

**四点的失败模式完全相同**：机位与 dense 不同、f88 就切了镜头、f104 换到第三个场景。

**时间跨度从 4 帧到 32 帧（8 倍）对内容漂移没有任何影响**：tt1 和 tt8 的失败模式完全一样
——机位与 dense 不同、f88 就切了镜头、f104 换到第三个场景。**而预算从 5% 到 20%（4 倍）
完全解决。** 帧对照表见 `artifacts/visual_checks/isotime/2026-10-11/sheets/`。

而且代价是反的：**`tt1` 比 `Veda2@20%` 还贵（19.2 对 16.0 s）却完全没用**。压扁 tile 让
gather 的局部性变差，成本上去、收益为零，**严格劣于加预算**。

### 排除法收敛了

| 候选 | 判定 | 证据 |
|---|---|---|
| 补偿 | ❌ 负贡献 | E4 单变量，控制臂逐位复现，两个独立实现互证（2.20 / 2.21） |
| 块几何（大小 / 形状） | ❌ | S-4 的 2×2，四格上「多选块胜过补偿」全成立（2.24） |
| **块的时间跨度** | ❌ | **本节，8 倍变化无影响** |
| 打分器 | ❌ | `veda1 − veda2` 的 flicker 差不显著（2.22） |
| **预算量** | ✅ | 5% → 20% 完全解决，阈值在 15~20% 之间（2.22） |

**所以「固定运行时间下效果最好」的答案就是把预算全花在密度上**，而不是花在补偿、

t102 用 10~15%（Sol 成本的 54~70%）。

### churn 的 50% 换血怎么解释

它在**任何** tt 下都存在——tt1 也漂。所以换血本身不是漂移的充分原因；
**决定内容能否跟住 dense 的是保留了多少质量，不是选择有多稳定。**
这也和 2.5 的 OT 框架一致：目标是保留质量，而不是选择的稳定性。

**能下**：融合的零阶补偿给 block-sparse kernel 加 **1.44~1.85×**，折算到整步是

## 3. 设计与不变量

### 3.1 低秩二阶头（`miowtion/veda/predictor.py`）

对角二阶项 `E[q^2] . Var(k) / (2D)` 本身就是两个 D 维向量的内积，也就是**又一个 rank-D
双线性**。所以：

- 塞进现有的 rank-D 双线性里，两项会互相挤占（`q_hat . k_hat` 只有 D 维输出，装不下
  `q̄·k̄` 和 `E[q²]·Var` 两个独立内积）；
- 给它一个独立的 rank-D 双线性，会让主导成本的 n² 项**翻倍**。

因此给它一个**低秩**的头：

```
logits = q_hat . k_hat / sqrt(D) + (sq_q @ So_q) . (var_k @ So_k)
```

`So_q`、`So_k` 是 `[num_heads, D, rank]`。n² 项的成本只增加 `rank / D`。

- `second_order_rank = 0`（默认）：**逐位等于改动前的打分器**，单测钉死。
- `second_order_rank = head_dim` 并调用 `init_exact_second_order_()`：**未训练的**打分器
  精确等于对数质量的完整对角估计，而不是零阶估计。这延续了现有设计里
  「未训练就已经是可用的块分数」那条思路。

成本账（16:9@37，366 tile，D=128，56 头，ρ=10%）。**注意：这张 FLOP 表预测错了瓶颈**，
实测开销在池化而不是 n²，见 §2.2：

| 项 | 每头 MAC | 占稀疏注意力 |
|---|---|---|
| 稀疏注意力本身 | 439 M | 100% |
| 打分器 embed（n·3D·D） | 18.0 M | 4.1% |
| 打分器双线性（n²·D） | 17.1 M | 3.9% |
| 二阶头，rank 16（n²·r） | 2.1 M | **+0.5%** |

### 3.2 池化：行数与二阶矩

`pool_tiles(x, layout, second=...)` 增加两个统计量：query 侧要原始二阶矩 `E[x²]`，
key 侧要中心化方差 `Var(x)`。`log B` 不需要新特征，它就是 `layout.valid_count`。

**方差必须两遍算**。一遍的恒等式 `E[x²] − E[x]²` 在一个块的行彼此接近时要相减两个几乎
相等的大数，而 RMSNorm 过的 key 在同一个空间块内本来就彼此接近：随机 layout 上实测相对
误差到过 **31%**，对一个要拿来排序的特征来说完全不能用。`_second_moment()` 因此先算均值
再减，按行分块以限制 fp32 临时显存，顺带把平方也放到 fp32 做。

**池化已经融合进 gather kernel**（`tile_gather_triton.gather_and_pool(..., second=True)`）。
这不是优化而是**全部开销所在**：实测只降 rank 不融合池化，每步还是 4.2 s；融合之后回到
3.94 s，和 Veda1 齐平（§2.2）。能这么干净是因为那个 kernel 本来就把整个 tile 读进了寄存器，
所以连**中心化**方差都不要额外的内存流量——均值在同一个 kernel 里刚算完，减掉它只是寄存器
上的运算。非融合路径（CPU、或 head_dim 不被 kernel 支持时）仍然走 `pool_tiles` 的两遍实现，
GPU 测试把两者对拍。

### 3.3 质量目标（`heatmap.py` / `kernels/block_heat_triton.py`）

`teacher_heat(..., reduce=)` 增加 `'sum'`：块内 `exp(s·scale − lse)` 之和，也就是块的注意力
质量，而不是块内最大值。默认仍是 `'max'`，所以现有调用点行为不变。

Triton kernel 里这是编译期分支（`SUM: tl.constexpr`），成本与 max 版本相同。
教师热力图只在**训练**期算，推理期不存在，所以这一项的推理成本严格为零。

为什么值得换：上表里 `A`（质量）补回 92~94%，`Mx`（最大）只有 64~85%，而且 `A` 与理想
重要性 `Ω` 的互 recall 是 0.941。**块质量几乎就是理想的选块目标**，而块内最大值不是。

### 3.4 静态每头预算（`solattn.py`）

H2 问过「同一个头里每行要不要各自的预算」，答案是不要（[sol_ablation](sol_ablation.md) §3）。
把同一个问题抬到**头**这一层，两条反对理由都变了：每头预算是离线校准出来的一个静态
数字，和 tile 方案表一样，所以一个头内部每行预算仍然均匀——没有负载不均衡、没有运行期
判断、没有 kernel 改动；而且分配器不是在用代理分数猜，它读的是**实测**的误差曲线。

`allocate_budget()` 在离散网格上做拉格朗日：给密度一个价格 `lam`，每个头独立选
`误差 + lam·密度` 最小的点，再对 `lam` 二分到平均密度命中目标。曲线是凸的时候这就是网格
受限问题的精确最优，并且满足通常的边际条件——**最优解处每个头的最后一个块买到的误差
下降相同**。返回的平均密度**从不超过**目标：会超的预算不叫预算。

实测（2800 个头、`proxy_topk`、同一总成本）：

| 目标 ρ | 总 ε 节省 | 每头 ρ 的 p10 / 中位数 / p90 |
|---|---|---|
| 0.071 | +3.89% | 0.050 / 0.070 / 0.091 |
| 0.102 | **+6.22%** | 0.062 / 0.100 / 0.144 |

## 5. 为什么零阶补偿不进 Veda2

补偿确实有效，ρ=10% 上 ε 降 10.6%，而且与选块质量互补（用 oracle 选块时收益更大）。
但等算力下它只是打平：

| ρ | 不补偿 | 补偿 | 把同样算力用来多选块 | 逐头配对：补偿更好的比例 |
|---|---|---|---|---|
| 5% | 0.34775 | 0.29657 | 0.31751（ρ'=0.0574） | 50.8% |
| 10% | 0.22109 | 0.19761 | 0.21130（ρ'=0.1070） | 58.5% |
| 20% | 0.13016 | 0.12028 | 0.12658（ρ'=0.2062） | 62.7% |

补偿一个丢弃块的成本是精确算一个块的 1/128（一次 `q·K̄` 加一次 `p̂·V̂`，对 128 个 key），
所以 ρ' 是把补偿的算力原样换成更多块之后的密度。

**中位数之比和逐头配对给出的结论不同，要用后者。** 按中位数之比，补偿（+14.7%）明显胜过
多选块（+8.7%）；但逐头配对下补偿只在 50.8~62.7% 的头上更好，ε 比值中位数 0.988~0.998，
也就是**只好 1% 左右**。两个臂的 ε 分布形状不同，中位数之比把差距放大了。配对才是同一个
头自己和自己比。

再加上 §5 的两项工程现实：块稀疏主循环遍历**被选中**的 18 个块而补偿要遍历**补集**的 348
个，需要独立 kernel 再借主 kernel 的 LSE 合并分子分母，反向也要重推；以及约 2% 的头会
**灾难性变差**（最差 −424%，集中在第 0、1 层，均场近似最差的地方）。换 1% 不值。

### 「训一个 adaptor 预测修正权重」：等成本上界已经否掉了

Sol 的补偿是「猜一个权重」乘「块内 V 均值方向」。把权重换成**真实的** `E_uj` 就是任何
权重预测器的等成本上界（每个丢弃块一个标量，和 Sol 一样），实现为 `c=2`：

| ρ | c=0 | c=1（Sol 猜的权重） | c=2（精确权重，等成本） |
|---|---|---|---|
| 5% | 0.34775 | 0.29657（+14.7%） | 0.29602（**+14.9%**） |
| 10% | 0.22109 | 0.19761（+10.6%） | 0.20445（**+7.5%**） |
| 20% | 0.13016 | 0.12028（+7.6%） | 0.12836（**+1.4%**） |

**把权重做准不但没用，密度一高还更差。** 原因在 §3 的拆解里：`c=2` 的分母是精确的 1，
它修掉了质量估计的 100% 误差，剩下的误差全部是**块内方向**——「块里到底是哪几个 key 被
attend 到」。给一个方向错误的向量配上更大更准的权重，只会把错误放得更大。单测
`test_oracle_mass_compensation_is_exact_when_v_is_block_constant` 钉死了这个分解：把每个
块的 V 设成块内常量（方向误差为零），`c=2` 的 ε 精确为 0，而 `c=1` 不是。

所以要在补偿上下功夫，该改的是**方向**而不是权重，而方向是每块一个向量，那就是 VSA 粗
粒度分支，本仓库已知它 fully train 之后无收益。

## 5.5 与相关工作的定位：创新点分级，以及一个明显的空洞

这一节是**分级**的，不是卖点清单。把「确实是我们的」「是别人的我们只是用了」「是别的
领域的已知结论我们搬过来」分开写，因为混在一起的清单在被人问第一个问题时就会垮。

### 三家的结构关系（先把事实摆对）

| 方案 | 稀疏精确路径 | 第二条（便宜的）路径 | 合并 | 训练 |
|---|---|---|---|---|
| Sol-Attn | 阈值 `μ+βσ` 选块 | 零阶补偿 | 加回 | training-free |
| VSA（[2505.13389](https://arxiv.org/abs/2505.13389)） | 细粒度 token 级块稀疏 | **cube 池化后的一次注意力** `O_c` | 学到的门：`O = O_c⊙G_c + O_f⊙G_f` | 端到端联合训练 |
| SLA（[2509.24006](https://arxiv.org/abs/2509.24006)） | critical 块的块稀疏 | **marginal 的低秩线性注意力**（O(N)） | 两路相加 | 少量微调 |
| **Veda2** | FA4 块稀疏 | **没有** | 不适用 | **完全 training-free** |

**先更正一条我自己写错过的**：我最初把 VSA 记成「粗粒度只用于选块」的纯路由器。那是错的。
VSA 的粗粒度注意力**输出被保留并经学到的门加权进最终输出**，论文说它
“is paramount for achieving optimal performance”。所以 **VSA 和 SLA 是同一类**（稀疏精确
路径 + 便宜的全局路径），**在这几家里 Veda2 是唯一纯丢弃的**。

另外，VSA 摘要自称 “a single differentiable kernel”，但论文自己又说 Top-K 迫使显式物化
coarse 注意力矩阵、因此 “FlashAttention cannot be directly applied to the coarse stage”。
而 Top-K 是离散的，论文没给穿过它的梯度路径。准确的说法是：**它的可训练性来自那条被保留
并加权的粗粒度路径，不是来自让 Top-K 可微**。

### A 级：我认为确实是我们的

1. **把块选择分数写成块对数质量的截断累积量展开，每一项都有闭式系数和已知代价。**
   于是「该加什么」从一个要靠搜索回答的问题，变成一个**可以静态回答**的问题。
   具体的新项是**对角二阶项 + 数据加权的低秩拟合**：
   `error(A,B) = tr(C_u M C_v Mᵗ)`，`M = ABᵗ − cI`，解是白化后矩阵的截断 SVD。
   rank 8 保住 rank 128 的全部收益（recall 0.7156 对 0.7167）。
   *注意边界*：「均值池化 QK 作为块分数」本身是公共知识——VSA 的粗粒度分数就是它，
   Veda1 未训练时也是它。**新的是「它只是零阶项」这个认识，以及下一项的闭式形式。**
2. **`mass` 对 `max`：从目标选择到闪烁的机制解释。** 块内最大值是**极值统计量**，
   由单个 token 对决定，方差大，所以相邻帧的同一个 query tile 容易因为一个 token 的抖动就
   换掉所选块；而质量是 16384 个分数之和。Veda1 用 max、Veda2 用 mass，人工确认
   **Veda1 全部 5 条 clip 闪烁、Veda2 没有**。这条把一个打分准则的选择和一个**具体的
   视觉失效模式**连起来，而且可以外推：任何 max 型或近似 top-1 的块分数都应该闪。
   *注意边界*：目前是「机制 + 人工确认」，**还没有量化**（mask churn 指标见 §7 待办）。
3. **等速、零训练、更好。** 3.938 对 3.944 s/step，训练量 600 步 → **0**，
   而块质量这个决定 ε 的度量上更优。这是对**我们自己基线**的结果，不是对文献的结果。

### B 级：别人的结论，我们做了非平凡的应用

4. **OT 视角下「按质量 top-k 是逐位最优」。** 把 attention 读成一侧的熵正则 OT 是
   [2508.08369](https://arxiv.org/abs/2508.08369) 的，**不是我们的**。我们的部分是把
   支撑集约束用到块稀疏上：`F(S) = log Σ_{v∈S} e^{s} = log E_u(S)`，于是
   (a) `argmax_{|S|=k} F(S)` 就是按块质量 top-k，(b) 次优间隙是 `−log(1−r_u)`，
   也就是 `kept/ceiling` **是目标本身而不是代理**。
   *诚实的限定*：一旦把约束问题写出来，这是**干净**的推论，不是困难的推论。它的价值在于
   把一个别人靠经验定的设计选择**定死**了（而且顺带说明块最大值不是任何 OT 问题的值）。

### C 级：别的领域的已知结论，我们搬过来并量化了

5. **规范不变性判据。** 「排序指标对分数的单调变换不变、而代理损失不不变」
   **在 learning-to-rank 里是已知的**，我们没有发现它。我们贡献的是三件具体的事：
   - 把它用到**稀疏注意力路由器的蒸馏**上，并用它**事后解释了四个目标的四种死法**
     （forward KL 摊平、reverse KL 锐化、原始 BCE 饱和、居中 BCE 上升）；
   - **指出逐行尺度就是 EOT 的温度 ε**（因为解是 `softmax(s/ε)`），于是
     forward / reverse 的失败是同一个 `∂/∂ε` 的两个符号——顺带验证了
     forward KL 恰好是 EOT 对偶势 `logsumexp` 的 Bregman 散度（实测差 1e-6）；
   - **量化了可微放松的下界**：五个保序映射下硬值逐位恒为 0.9141，软值在 0.632~0.841
     之间摆；slack 以 t = 7~12 增长而 `logit_std` 无趋势。
     唯一对单调群不变的统计量是秩，而秩的梯度几乎处处为零，**所以这是方法下界而不是 bug**。
   - 对 VSA 这类方案尤其值得说：它的选块分数拿到的梯度是**间接**的（穿过 `O_c` 和门，
     不穿过 Top-K），那条路径优化「池化注意力输出好不好」，与「Top-K 排序对不对」
     只是相关——**同一个规范问题在那里以另一种形式存在**。

6. **三条有用的负面结果**，但每条都有明确的射程：
   - 零阶补偿**等 FLOP 下是平局**（逐对胜率 50.8~62.7%、中位优势 1%）；
   - 每行可变预算**不划算**，因为瓶颈是打分器准确度（18~43%）而非选块目标（7~10%）；
   - **完整二阶比对角更差**（ρ=5% 时 38.8% 对 46.0%）——截断的累积量展开不保证加更多项更准。

### 最大的弱点：两个

**① 没有共同基准上的横向对比。** VSA 在 Wan-2.1 上、SLA 在 Wan2.1-1.3B 上、我们在
MiniMax-H3 33B 上，速度数字没有共同坐标轴。任何「我们更好」的说法目前都**不成立**，
也不应该写。我们能说的只有「在同一个 kernel、同一个模型、同一个 seed 下，Veda2 零训练
超过训练 600 步的 Veda1」。

**② 「要不要加第二条便宜路径」是空的，而两家都有。** 我们只否掉了**零阶**补偿；
VSA 的 `O_c` 是一次真正的（池化上的）注意力，SLA 的是 O(N) 低秩线性注意力，
**表达力都严格更强，SLA 那条还便宜得多**。所以我们的否定结论**不能外推到它们**。
能外推的只有判据本身：**第二条路径的价值要和「同样算力换更多块」比，不是和
「什么都不补」比。** 这是被问到的第一个问题，而我们没有答案。见 §7 待办。

## 7. 待办（按价值排序）

1. **在固定 holdout 上确认那 +0.009**（§2.7）。现在全部测在训练流上，每个 update 换一条
   片子，而 `docs/features/evaluation.md` 写明同几何换片子 `heat_ceiling` 能差 4%，
   和要测的效果同量级。`predictor_precision.py` 的 `--bundle` 可以给多次，在**同一条
   片子、同一几何、同一 seed** 上并排评，彻底去掉混淆；先用 `export_predictor.py` 从
   `runs/stage1_veda2_transport_refine_t37/ckpt/step_0000100` 导出 bundle。
   量级参照：Veda2 超 Veda1 是 recall 0.7159 对 0.6331，那个差距以**闪烁**的形式肉眼
   可见；+0.009 只是它的小零头，**很可能看不出来**，所以这一步的结论很可能是「不值得」。
2. **回答「要不要加第二条便宜路径」**（§5.5 的空洞）。VSA 用 cube 池化后的一次注意力、
   SLA 用 O(N) 低秩线性注意力，两者**表达力都严格强于**我们否掉的零阶补偿。
   正确的判据是**和「同样算力换更多块」比**，不是和「什么都不补」比。
   最小实验：在 `solattn.relative_errors` 里加一个「低秩线性补偿」变体，
   用现成的等 FLOP 配对协议（§5 零阶补偿那套）跑一遍。这是被问到的第一个问题。
3. **量化闪烁**（§5.4 的机制目前只有人工确认）。mask churn 指标：相邻去噪步之间、
   以及时间上相邻的 query tile 之间，所选集合的重叠度。预期 max 目标显著低于 mass 目标，
   这会把 A 级第 2 条从「机制 + 人眼」升级成测量。
4. **跑完一次完整的训练**，用 §2.4 推出来的 `transport_loss`。已跑到 163 步并确认平台
   （§2.7），所以这条现在的优先级低于上面三条：先确认 +0.009 值不值得，再决定要不要
   跑满。
5. **放开二阶头**（`freeze_second_order: false`）**要先换参数化**。现在它在
   `so_q`/`so_k` 上是二次的，所以会跑飞（§2.3 ③）。该改成
   `g_h · (归一化的项)`，`g_h` 是每头一个标量（线性、良条件），子空间冻结或给低一两个
   数量级的 lr。这把「这个特征值多少」和「哪个子空间」解耦。
6. **三类参数必须分 param group**：`proj` 初值 1e-4、`so_*` 0.0625、`count_gain` 1.0，
   差四个数量级，而 Adam 步长与初值无关。统一 lr 对三者分别是每步 10 倍 / 1.6% / 0.1%。
7. **放宽预算分配的实测范围**到 ρ∈[0.02, 0.4]，现在的 6.2% 是被 [0.05, 0.206] 的网格
   夹住的下界。
8. **把发布的打分器放进 ε 的度量里**。§2.1 已经在 recall / heat_kept 上量过它，但
   §2 那张「补回差距比例」的表里所有「proxy」仍然是**未训练**的池化分数。把
   `veda1_trained` 的 logits 接进 `scorer_masks` 就能补上这一格。
9. 在 `count_term_leverage` 低的几何上复跑一遍完整的 Veda2（不只是 `log B`）：
   二阶项没有这个 layout 依赖，所以它在双采 regime 上应该仍然有效，但没有实测。
10. 打分器的**去噪步条件化**：现在打分器不吃 t，而实测丢弃质量从 step 0 的 0.431 降到
   step 7 的 0.252，最优排序可能随步漂移。
