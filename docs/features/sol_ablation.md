# Sol-Attn 消融：选块目标与每行预算

## 目标

在**冻结 backbone**、**不训练**、**不写 kernel** 的前提下，只用导出的 Q/K/V 离线回答两个
问题，决定 Veda 下一步往哪走：

- **H1（选块目标）**：以「对输出误差的贡献」选块，是否优于以「注意力质量」选块
  （Veda 现在的蒸馏目标是块内最大概率 `Mx`）。
- **H2（预算分配）**：每行可变预算（Sol 原版 `μ+βσ` 阈值，或本文提出的 `σ` 自适应阈值）
  是否优于固定 top-k。

对照的两篇：Sol-Attn（arXiv 2607.24027，免训练，阈值选块 + 零阶补偿）、
Veda（arXiv 2605.30325，蒸馏打分器 + 固定 top-k + 直接丢弃）。

已知的负面结果（本仓库此前的实验）：VSA 粗粒度分支、SLA 线性分支的补偿在 fully train 之后
都没有收益。所以这次先用最便宜的方式验证假设，再决定要不要训练。

## 设计与不变量（`miowtion/veda/solattn.py`）

### 一个恒等式统一两种设定

对 query token `u`（在 query tile `i`）、保留集 `S_i`、丢弃集 `U_i`，以及
`c ∈ {0,1}` 表示是否对丢弃块做 Sol 的零阶补偿：

```
O_u^(M,c) − O_u = −(Z_u / D_u) · Σ_{j∈U_i} ξ_uj
ξ_uj = (ΔN_uj − ΔE_uj · O_u) / Z_u
```

其中 `ΔN_uj = N_uj − c·N̂_uj`、`ΔE_uj = E_uj − c·Ê_uj` 是块的近似残差。
**「直接丢弃」就是 `c = 0`**，所以两种设定共用同一条代码路径，不需要两套实现。

投到该 head 的输出投影切片之后，三角不等式给出的上界对选块是线性的，于是块级理想重要性是

```
Ω_ij^(c) = Σ_{u∈I_i} ‖ ξ_uj^(c) · W_o^h ‖₂
```

固定每行 `k` 时按 `Ω` 取 top-k 是该上界的精确最小化解；总预算固定时按 `Ω` 取**全局阈值**
是最小化解（每行最后一个被选块的边际收益相等）。这两个构成 H2 的 2×2 里的 oracle 那一行。

### 三条实现上必须守住的性质

1. **一切按 dense 的 log-sum-exp 归一化**。表里存的是 `a_uj = E_uj/Z_u` 和
   `n_uj = N_uj/Z_u`，于是 `Σ_j a_uj = 1`、`Σ_j n_uj = O_u`。好处有两个：fp32 不会上溢，
   并且「全保留」的误差**精确为 0**（单测断言这一点）。
2. **`‖x·W_o^h‖` 永远不在 hidden 空间里展开**。令 `S` 是 `out_proj.weight` 该 head 的列
   切片、`G = W_o^h W_o^hᵀ = SᵀS`、`G = LLᵀ`，则 `‖x W_o^h‖ = ‖x L‖`。整个消融都在
   head_dim（128）里做，不碰 hidden_size（6144）。`whitening()` 每个 head 只算一次 L；
   切片秩亏时退到特征值裁剪的平方根（不静默，只是另一种精确做法）。
3. **Ω 需要保留 head_dim 轴的 `n_uj`**，即每个 query tile 一块 `[U, N, D]`，比注意力本身
   贵 N 倍。所以**必须抽样 query tile**（`query_tiles`，默认 8），和 tile 方案搜索一样。
   这是全局 `[R, N]` 分数表能便宜、而 Ω 不能全量算的根本原因。

### 两遍扫描，所有掩码共用一次注意力

每个 `(layer, head, step)`：

- **第一遍** `head_tables()`：算出 `[R, N]` 的分数表 `A`（块注意力质量）、`Mx`（Veda 现
  目标）、`Ω⁰`、`Ω¹`、代理分数 `s̃`（块均值内积）以及每行的 `μ`、`σ`。全是标量表，便宜。
- **中间**：按分数表构造所有掩码。R2/R3/oracle 阈值的参数在**每个 head 内**校准到平均密度
  恰好等于 `ρ`（`calibrate_threshold`，取池化后第 k 大与第 k+1 大的中点，`>` 严格比较时
  计数精确），因此比较的只是「同一 head 内各行之间怎么分配」，总成本完全一致。
- **第二遍** `relative_errors()`：所有掩码 × `c ∈ {0,1}` 由同一组 `{a, n, â, n̂}` 组合出
  稀疏输出，**没有任何掩码重算注意力**。

### 预算与文本 token

- `density` 是**所有** key tile 的保留比例。全局（文本 / 条件）key 块**始终保留并计入
  预算**，`video_budget()` 把剩下的给视频象限；全局块本身就吃掉超过 `ρ` 时直接 `raise`。
- 全局 **query** 行在 Veda 里本来就走稠密，没有选块可消融，所以不抽样；
  `head_tables()` 收到非视频 query tile 会直接 `raise`。
- 固定 top-k 的小数预算用 Veda 训练里同一个 Bresenham 模式铺到各行（`bresenham_extra`，
  相位跟 tile id 而不是在 `rows` 里的位置），所以平均密度精确命中，并且和训练一致。
- 为了让比较纯粹，消融里的 top-k **不强制对角块**（生产 Veda 会强制）。各规则因此共享完全
  相同的可选支撑集。

### 对比的规则（`allocation_masks`）

| 名字 | 条件 | 参数 |
|---|---|---|
| `R1_topk` | 每行按 `s̃` 取固定个数 | — |
| `R2_zscore` | `(s̃−μ_i)/σ_i > β` | `β` 校准到密度 `ρ` |
| `R3_sigma_a<α>` | `s̃ > μ_i + α·σ_i²/2 + c`，可选 `k_min/k_max` 夹紧 | `c` 校准；扫 `α` |
| `R2g_zscore_global` | `β = Φ⁻¹(1−ρ)`，全模型共用、不校准 | 单独汇报 |
| `oracle_topk` | 每行按 `Ω` 取固定个数 | — |
| `oracle_threshold` | `Ω > λ`，全局阈值 | `λ` 校准 |

`α` 要扫是因为块均值后的分数方差小于 token 级方差，`σ²/2` 的系数未必是 1。
`k_min/k_max` 既做负载均衡，也兜底重尾时 `μ+σ²/2` 对 log-sum-exp 的低估。

**为什么 z-score 阈值值得试、又为什么它不占 top-k 的便宜**：z-score 对平移和缩放不变，
所以一个 `β` 可以跨层 / head / 步通用，这点强于 top-p 和绝对阈值；但 top-k 对**任意**单调
变换都不变，所以 z-score 并不比 top-k 更「通用」。它真正多出来的信息是 `σ_i` 本身携带的
「这一行有多尖锐」——推导里最优 `β_i* = σ_i/2 + c/σ_i` 随 `σ_i` 变化，这正是 R3 在试的。

### 两道门槛（`summarize`）

- **G1**：大多数 `(l, h, t)` 上 `ε(Ω⁰) ≤ (1−η)·ε(Mx)`（默认 `η = 15%`，`c = 0`）。
  不过就说明瓶颈不在选块目标，而在打分器的特征表达能力，「换蒸馏目标」不值得训练。
- **G2**：2×2 第二行（oracle 分数下）固定 top-k 与全局阈值的相对差距 > 5%。
  不过就说明可变预算本身价值不大，R2 与 R3 不必细比。

### 机理诊断（第 4 节）

`row_moments`（D1：z-score 的偏度 / 超额峰度）、`proxy_omega_spearman`（D2：按 z 分区算
`s̃` 与 `Ω` 的 Spearman，检验「bulk 里排名近乎噪声」）、`load_imbalance`（每行保留数的
max/mean，决定 kernel 最慢线程块的拖尾）、`dropped_mass`（D5：丢掉的注意力质量 `r_u`）。

- `miowtion/veda/solattn.py`

  - `zscore_statistic` / `sigma_adaptive_statistic`
  - `selection_masks`（H1 的四种）/ `allocation_masks`（H2 的六种）
  - `head_report` / `Record` / `summarize` / `save_records` / `load_records`
  - `AblationScorer`（AttentionFn）/ `AblationConfig` / `RunConfig` /
    `ablate_clip` / `run_ablation`
- `scripts/ablate_sol.py`：`--config` 跑，`--summarize` 重新打印已存的 run。
- `configs/ablate_sol_turbo8_16x9_t37.yaml`、`configs/ablate_sol_base50_16x9_t37.yaml`

**单进程运行**：输出投影必须未分片。`_dense_weight` 见到 DTensor 直接 `raise`——在
attention 回调里 all-gather 是集合通信，而各 rank 跑的是不同 clip，必然对不上。
`run_ablation` 在 `world_size != 1` 时也直接 `raise`。

## 用法

```bash
python scripts/ablate_sol.py --config configs/ablate_sol_turbo8_16x9_t37.yaml
python scripts/ablate_sol.py \
    --summarize runs/sol_ablation_turbo8_t37/16x9_t37.json
```

输出 `runs/<run_name>/<geometry>.json`：`meta` + 每 `(clip, step, layer, head, density)`
一行 `records` + `summary`（两道门槛的判定）。

## 测试

`tests/unit/test_veda_solattn.py`（41 项，CPU）：

- **独立对拍**（这是信心的主要来源）：`c = 0` 的 ε 对上「只在保留块上重新 softmax」的
  逐 token 暴力实现；`c = 1` 的 ε 对上逐块累加的零阶补偿暴力实现（都 rel 2e-3）。
  `Ω⁰` 对上按定义逐 token 累加 `‖(n_uj − a_uj O_u) W_o‖` 的实现。
- 全保留时 ε ≈ 0；ε 随密度单调下降；`Σ_j a_uj` 等于该 tile 的真实行数。
- 掩码是纯数据变换，用 `torch.equal` 对参考循环：`fixed_topk_mask` 逐位相等；
  平均密度精确命中；`threshold_mask` 的 `k_min/k_max` 夹紧精确；
  `calibrate_threshold` 的平均保留数精确。
- `whitening` 的行范数等于直接乘 `W_o` 的行范数；秩亏切片不炸。
- G1 / G2 判定按构造好的 Record 验证边界；Record 的 json 往返。
- `AblationScorer` 返回的注意力与 `dense_attention` **逐位相同**（`torch.equal`），
  head 过滤生效，非视频 query 行被拒；另有一项用 tiny 配置把整个 `H3DiT.forward`
  跑通（out_proj 查表、plan 分组、50 层都出记录）。
- `dropped_mass_r1` 是**每 token** 的比例（除以每个 tile 自己的真实行数），在 (0, 1) 内。

`tests/unit/test_configs.py`：`ablate_*.yaml` 必须能解析成 `solattn.RunConfig`。

GPU 测试：暂无（这条路径没有自己的 kernel，稠密注意力和 tile gather 都复用已验证的实现）。

## 踩坑记录

- **三角不等式上界在 `c = 0` 时很松，不能当成 ε 来做单测断言**。
  现象：一开始写了个单测断言「随机 Q/K/V 上 `Ω⁰` top-k 的 ε 小于 `Mx` top-k」，结果反过来
  （1.97 vs 1.77）。
  原因有两层：（a）`c = 0` 时 `Σ_j ξ_uj = 0`，块间误差可以互相抵消，按 `Σ‖ξ‖` 取 top-k
  最小化的是上界而不是 ε 本身；（b）iid 高斯的 Q/K 让注意力接近均匀，每块贡献几乎一样，
  根本没有「该选哪些块」的信号可言。
  对策：**H1 是实验要回答的问题，不是可以单测的不变量**。改成在构造出的信号上测机制——
  分数极小（注意力近均匀，`A`/`Mx` 的排名近乎随机）、但 V 的范数按块差很多，此时 `Ω` 必须
  赢。断言的是「机制能找到承载输出的块」，而不是「真实层长这样」。
- **`dense_attention` 即使 `return_lse=False` 也返回 tuple**（第二项是 `None`）。
  单测里直接 `torch.equal(out, dense_attention(...))` 会报 "must be Tensor, not tuple"。
- **pad query 槽 gather 到第 0 行**：和 tile 搜索同一个坑。这里的做法是在归一化概率上乘
  `row_valid`（pad 行整行置 0），所有后续量（`a`、`Ω`、ε 的分子分母）都自动不受污染。
- **`proxy` 在全局列上是 NaN**，这是故意的：代理分数只在视频象限有定义，全局列无条件保留，
  不参与任何阈值或排名。所有读 `proxy` 的地方都只取前 `n_video_tiles` 列并按 `kv_ok` 过滤。
  在全局列上算 `μ`/`σ` 会把整行污染成 NaN。

## 结论（2026-10-08，真实权重实测）

**两道门槛都没过。不要做「方式 A」，也不要换成可变预算；真正的瓶颈是打分器的准确度。**

数据：16:9@37（38010 token、366 个 tile）、8 步 Turbo 教师 + 发布的 step600 LoRA、
`moviegen_holdout20` 的 2 条 prompt × 步 {0,2,5,7} × 50 层 × 56 头 × ρ∈{5%,10%,20%}
= 67200 行，每行抽 6 个 query tile。

### H1：选块目标不是瓶颈（G1 FAIL）

`c=0` 下各目标的 ε 中位数：

| ρ | `Mx`（Veda 现目标） | `Ω⁰`（理想重要性） | `A`（注意力质量） | `R1`（真实代理分数） |
|---|---|---|---|---|
| 5% | 0.3072 | 0.2840 | 0.2885 | 0.3478 |
| 10% | 0.1678 | 0.1562 | 0.1614 | 0.2211 |
| 20% | 0.0821 | 0.0738 | 0.0772 | 0.1302 |

- 换成 `Ω⁰` 只降低 **7~10%** 的误差，达到 G1 要求（≥15%）的头只有 18.5% / 19.5% / 24.8%，
  远不到半数。按步拆开是 17% / 20% / 20% / 20%，**不随去噪步变化**，不是时机问题。
- 更关键的是 **`A`（纯注意力质量）几乎和 `Ω⁰` 一样好**（ρ=5% 时 0.2885 vs 0.2840，差 1.6%）。
  也就是说「对输出误差的贡献」这个更贵的目标，相对「块注意力质量」几乎没有额外信息；
  Veda 现在用块内**最大**概率而不是块**总**质量，才是那 7~10% 的来源。
- 对比两个差距：

  | ρ | 打分器准确度的代价（`R1` → `oracle_topk`） | 换目标能拿到的（`Mx` → `Ω⁰`） |
  |---|---|---|
  | 5% | **18.3%** | 7.6% |
  | 10% | **29.3%** | 6.9% |
  | 20% | **43.3%** | 10.1% |

  打分器不准造成的损失是换目标收益的 **2.4~4.3 倍**，而且随密度升高差距还在拉大。
  方式 A 的天花板（oracle）本来就低，训练出来的打分器只会更低。

### H2：每行可变预算不划算（G2 FAIL）

oracle 分数下固定 top-k 与全局阈值的差（正数表示可变预算更好）：
ρ=5% **−2.2%**、ρ=10% **+1.0%**、ρ=20% **+4.5%**。即使分数完全准确，可变预算在稀疏端
是**负收益**，只有在密度升到 20% 时才接近（仍未达到）5% 的门槛——而 20% 已经不是稀疏加速
关心的区间。

用真实代理分数时，所有可变预算规则都**不如**固定 top-k：

| ρ | `R1_topk` | `R2_zscore` | `R3_σ α=0.5` | `R3_σ α=1` | `R3_σ α=2` |
|---|---|---|---|---|---|
| 5% | **0.3478** | 0.3773 | 0.3999 | 0.3920 | 0.4867 |
| 10% | **0.2211** | 0.2250 | 0.2302 | 0.2317 | 0.2939 |
| 20% | **0.1302** | 0.1303 | 0.1304 | 0.1337 | 0.1720 |

扫 `α` 没有救回来：`α` 越大越差，说明 `μ+ασ²/2` 这个偏移方向本身就不对。

还有一笔没算进 ε 的成本：**负载不均衡**。固定 top-k 的 max/mean 是 1.006~1.059，
R2/R3 是 1.10~2.03，oracle 全局阈值 1.45~1.65。kernel 的尾延迟由最慢的线程块决定，
所以可变预算即使 ε 打平也是净亏。

`R2g_zscore_global`（全模型共用 `β=Φ⁻¹(1−ρ)`、不按头校准）的 ε 看起来最低
（ρ=5% 时 0.2653），**但它是多花预算换来的**：实测每行保留 50.25 个视频 tile，而校准过的
规则是 29.5 个，多了 70%。这正是本文档要求它单独汇报的原因，不能和校准过的规则并列比较。

### 机理：Sol 的前提在这个模型上不成立

- **D1 成立**：代理分数的 z-score 接近高斯（偏度 +0.286，超额峰度 −0.190）。所以可变预算
  失效不是因为高斯假设被破坏。
- **D2 反了**：`s̃` 与 `Ω⁰` 的 Spearman 在 **bulk（|z|≤1）是 0.541**，在**右尾（z>1）只有
  0.389**。Sol 的论据是「bulk 里排名近乎噪声、右尾才有信息，所以该按离群程度分配预算」，
  实测恰好相反——代理分数在 bulk 里反而**更**可靠。按右尾阈值选块、让 bulk 饿着，自然
  比均匀地每行取 top-k 更差。这一条是 H2 失败的直接原因。
- 补偿（`c=1`）在所有设定下都稳定降低误差（例如 ρ=10% 的 `R1` 0.2211 → 0.1976，降 11%），
  并且 `Ω¹` 与 `Ω⁰` 的选块差异很小（ε 差 0.3% 以内）。**补偿值得单独评估**，但它不改变
  「该精确算哪些块」的结论。

### 下一步

1. **不做**方式 A（换蒸馏目标）。如果要在目标上动，最便宜的改动是把 `Mx` 换成块总质量
   `A`，它拿到的和 `Ω` 几乎一样多，而且不需要 `W_o`、不需要额外的 [queries, tiles, dim]
   计算，教师热力图的 kernel 改动也最小。
2. **不做**可变预算。固定 top-k 保留。
3. 把力气放在**打分器准确度**上（18~43% 的差距都在这里）：更强的 tile 池化特征、
   更大的 `d'`、或者按层 / 按步条件化。
4. 零阶补偿（`c=1`）本身有 10% 左右的稳定收益，值得单独立项评估它在 kernel 里的成本。
